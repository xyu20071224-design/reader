### 5.1 T1.7 统一章内进度算法

**现状**（`src/app/src/main/java/com/linguareader/app/reader/ReaderScreenState.kt`）：

- `progress(chapterCount)` **L139–143**（顶栏进度条/书架续读用，读**实时** `page/pageCount`）：
  ```kotlin
  fun progress(chapterCount: Int): Float {
      if (chapterCount <= 0) return 0f
      val inChapter = if (pageCount <= 1) 0f else page.toFloat() / (pageCount - 1)
      return (chapter + inChapter) / chapterCount.toFloat()
  }
  ```
- `saveRequest(chapterCount)` **L146–158**（落盘用，读**快照** `savedPage/savedCount`）：
  ```kotlin
  val inChapter = if (savedCount <= 1) 0f else savedPage.toFloat() / (savedCount - 1)
  val progress = if (chapterCount <= 0) 0f else (chapter + inChapter) / chapterCount.toFloat()
  ```

问题：分子/分母的「章内比例」公式被复制两份；且两处对 `chapterCount<=0` 的守卫位置不一致（`progress` 先守卫后算 inChapter，`saveRequest` 先算 inChapter 后守卫）。

**做法**：抽一个私有 helper 统一章内比例，两个公开函数各自传自己的 `(page, count)`，**保留「实时 vs 快照」的差异**（这是语义，不是 bug）：
```kotlin
/** 章内进度 0..1；整章一页(count<=1)视为 0（进度增量由章号承担）。 */
private fun inChapterRatio(page: Int, count: Int): Float =
    if (count <= 1) 0f else page.toFloat() / (count - 1)

fun progress(chapterCount: Int): Float {
    if (chapterCount <= 0) return 0f
    return (chapter + inChapterRatio(page, pageCount)) / chapterCount.toFloat()
}

fun saveRequest(chapterCount: Int): ReaderProgressSave? {
    if (!dirty) return null
    val progress = if (chapterCount <= 0) 0f
        else (chapter + inChapterRatio(savedPage, savedCount)) / chapterCount.toFloat()
    // ...其余不变
}
```

**完成标准**：`ReaderScreenStateTest` 全绿；无行为变化（纯提取，不改数值），既有进度用例覆盖即可。
