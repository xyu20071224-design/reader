> 状态：**改动已落地，构建侧已实测通过；真机冒烟未做。**
> 实测结果：release APK **45.38 MB → 33.3 MB，减少 12.07 MB（26.6%）**。
> 已改：`build.gradle.kts`（开 minify + shrinkResources）、`proguard-rules.pro`（keep 规则）、
> 新增 `src/app/src/main/res/raw/keep.xml`（资源白名单）。
> **仍未做：真机冒烟**——R8 的坑基本都是"不崩溃、只是功能静默失效"，构建通过不等于没坏。

## 1. 结论先说

`release` 确实没开 R8，**代码压缩、混淆、资源裁剪三样全丢**：

| 位置 | 现状 |
| --- | --- |
| `src/app/build.gradle.kts:36` | `isMinifyEnabled = false` |
| `src/app/build.gradle.kts:37-40` | `proguardFiles(...)` 已声明，但 minify 关着，等于空转 |

也就是说：当前发版包里带着 Compose / pdfbox / jsoup 的全部未用代码和全部未引用资源。

**但直接把 `isMinifyEnabled` 翻成 `true` 会出线上事故**，有两个必须先堵的坑（第 3 节），因为规则文件是空的。

## 3. 两个必堵的坑（复述重点）

1. **JS 桥方法名**——阅读器的核心交互全走这条链路，坏了不崩溃、只是"点了没反应"，最难在灰度里发现。
2. **`getIdentifier` 的 9 个音色名**——正是"资源裁剪"最典型的反噬点，裁掉后不崩溃，只是 UI 显示成资源 key。

这两个都是**静默失效**，不会抛异常，所以单测和"能装能启动"的冒烟都测不出来，必须针对性验证。

## 4. 已落地的改动（未验证）

### 4.1 `src/app/build.gradle.kts`

```kotlin
release {
    isMinifyEnabled = true
    isShrinkResources = true          // 新增：资源裁剪依赖 minify
    proguardFiles(
        getDefaultProguardFile("proguard-android-optimize.txt"),
        "proguard-rules.pro"
    )
}
```

### 4.2 `src/app/proguard-rules.pro`

```proguard
# WebView JS 桥：JS 按方法名调用，方法名不能混淆（reader/EpubPage.kt）
-keepclassmembers class * {
    @android.webkit.JavascriptInterface <methods>;
}

# pdfbox-android 引用了 Android 上不存在的桌面 Java 类
-dontwarn java.awt.**
-dontwarn javax.imageio.**
# 实际清单以首次构建产出的 build/outputs/mapping/release/missing_rules.txt 为准
```

### 4.3 新增 `src/app/src/main/res/raw/keep.xml`

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources xmlns:tools="http://schemas.android.com/tools"
    tools:keep="@string/tts_mimo_voice_*" />
```

对应 `res/values/strings.xml:556-564` 的 9 个 key（`values-en` 同名同数）。

## 6. 顺带发现的环境事实（值得写回记忆库）

`AGENTS.md` 没提这些，是我这次踩出来的：

1. **`JAVA_HOME` 默认没设**，直接 `.\gradlew.bat` 报
   `ERROR: JAVA_HOME is not set and no 'java' command could be found`。
2. **默认 `GRADLE_USER_HOME`（`C:\Users\nagisa\.gradle`）不可用**，wrapper 报
   `Could not create parent directory for lock file`。
3. **正确入口是 `toolchain\build.ps1`**，它统一设好：
   `JAVA_HOME`=Temurin 17.0.20.1、`ANDROID_HOME`=`<toolchain>\android-sdk`、
   `GRADLE_USER_HOME`=`<toolchain>\gradle-home`（已含 gradle-8.11.1-bin 与依赖缓存）、
   `USERPROFILE`/`HOME`/`TMP` 重定向、代理 `127.0.0.1:7890`。
   构建命令即：`powershell -NoProfile -File <仓库根>\toolchain\build.ps1 assembleRelease`。
4. **工具链会搬家**：本次会话中途它从 `C:\work\toolchain` 被移到了仓库内
   `C:\work\reader\toolchain`（脚本已改成用 `$PSScriptRoot` 自解析路径，所以搬完仍可用）。
   **不要在任何地方硬编码工具链绝对路径**，照着脚本走即可；`src/local.properties` 的
   `sdk.dir` 会随之失效，需同步更新（该文件已被 `.gitignore` 忽略，不进提交）。
5. **本机没有 `pwsh`（PowerShell 7）**，只有 Windows PowerShell；
   调 `build.ps1` 要用 `powershell -File`，或把上面那组环境变量内联进命令。
