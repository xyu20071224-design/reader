## 1. 三份报告的交叉核对（先解决分歧）

### 1.1 单测能不能跑？—— 我推翻了自己的初判

| 说法 | 来源 | 裁定 |
|---|---|---|
| "中文路径导致 Gradle 用 @argfile 传类路径、Java 按 GBK 读 → ClassNotFoundException" | 重建报告 | ✅ **机理正确** |
| "是审查沙箱禁止写子进程 stdin 导致的，非项目缺陷" | **我的初判** | ❌ **错误，已撤回** |

**实测复现（三组对照）**：把一个 `-cp <含中文的 jar 路径>` 的 argfile 分别按两种编码写盘，再用 `java @argfile` 启动同一个主类：

| 试验 | 结果 |
|---|---|
| argfile 存为 **UTF-8** | ❌ `ClassNotFoundException: ?-cp` —— JVM 启动器按 GBK 解码，整行糊掉，`-cp` 都不再被识别为选项 |
| argfile 存为 **GBK** | ✅ 正常加载（仅因无握手数据抛 EOFException） |
| 对照：直接 `-cp <含中文路径>`（不走 argfile） | ✅ 正常加载 |

**完整因果链**：`gradle.properties:1` 给守护进程设了 `-Dfile.encoding=UTF-8` → 守护进程按 UTF-8 写出 worker 的 `@gradle-worker-classpath*.txt` → 但 worker 的 **JVM 启动器解析 @argfile 用的是平台编码**（本机 `sun.jnu.encoding=GBK`，且不受 `-Dfile.encoding` 影响）→ 路径里的 `语境阅读` 被解成乱码 → 类路径失效 → `ClassNotFoundException: GradleWorkerMain` → worker 秒退 → 守护进程随后报 **`Could not write standard input to Gradle Test Executor N`**。

**我之前正是把最后这条下游症状当成了根因**。路径为纯 ASCII 时 UTF-8 与 GBK 字节相同，所以搬到 `C:\work\` 就好了——这解释了重建报告的成功。

### 1.2 新增：无需搬家的修复（已实测生效）


**81 个失败的唯一原因是离线**：逐个解析 60 份结果 XML，**81/81 全部是 `Robolectric` 的 `MavenDependencyResolver` 取不到 `android-all` 依赖**（`FileNotFoundException`），且 15 个失败套件都是**整套全挂**（4/4、10/10、9/9…）——典型的"Robolectric 起不来"，不是逻辑断言失败。**334 个纯 JVM 用例全部通过。**

**⚠️ 采纳前必须验证**：我这次跑的编译任务是 `up-to-date`（未重新编译），所以 **`file.encoding=GBK` 对含大量中文字面量的 Kotlin/Java 源码编译有无副作用，本轮未验证**。建议顺序：① 首选保持 ASCII 路径（重建报告已证 416/0）；② 若坚持留在中文路径，先 `clean` 后完整验证一次再固化到 `gradle.properties`；③ 或开启 Windows「Beta: 使用 Unicode UTF-8 提供全球语言支持」，令 `sun.jnu.encoding=UTF-8` 从根上消除错配。

### 5.4 中危要点（择要）

- **AI 取消语义**（`ai/OpenAiCompatTranslator.kt:47-79` + `JsonChatTranslator.kt:113-114`，readTimeout **300 s**）：阻塞式 `HttpURLConnection` 不响应协程取消，点"取消生成"后最长约 **5 分钟**仍显示生成中且无法重开。
- **精译检查点静默降级**（`ai/AiTranslationRepository.kt:280-283` 写、`:302-313` 读）：初翻稿也落盘且读取不校验 `mode` → 精译任务中断续跑会**复用未精修的初稿**，用户无感知。
- **重试无退避 + 一批失败即整本中止**（`:267-294`、`:88-101`）：命中 429/5xx 立刻重撞；最坏 4×300 s 后整本停摆。
- **无音频焦点管理**：全树 grep `AudioManager`/`requestAudioFocus`/`BECOMING_NOISY` **零命中** → 与音乐混音同放、来电不让路、拔耳机继续外放。
- **`stopped` 单一 volatile 竞态**（`tts/CloudTtsSynthesizer.kt:93,172-180`）：旧句晚归可顶掉新句 → **播放静默卡死**。
- **旧数据迁移可致书架永久为空**（`data/LibraryRepository.kt:110-119`）：`.map` 急切求值，v1 `library.json` 中一条坏记录就让整批迁移放弃，异常被空 catch 吞掉且旧文件不删 → 每次启动重试再失败。
- **元数据损坏静默丢书**（`:31-33`）：坏 metadata.json 的书**无提示地从书架消失**；`:99-108` 的 rename 回退路径还是非原子直写。
- **文案未转义可致阅读器白屏**（`reader/ReaderScripts.kt:366,370`）：`scrollEndHint/scrollStartHint` 是全文件**唯二**未走 `JSONObject.quote` 的插值；当前 zh/en 文案恰好无撇号，但英文改成含撇号的文案即整段 bootstrap 语法错误。
- **主线程 I/O**：`AppViewModel.kt:175`（启动即 SharedPreferences + Keystore 解密）、`:273-288`（删书递归删数百个检查点文件）、`BookshelfScreen.kt:596-597`、`ReaderScreen.kt:242-258`。

### 5.5 贯穿全项目的反模式：**把失败当成功**

同一模式在**四个互不相干的层**独立出现，值得作为规约整改：

| 层 | 位置 | 表现 |
|---|---|---|
| 工作台后端 | `studio.py:576,586` | 无条件 `ok:True`，属主校验拒绝/启动失败也报成功 |
| 工作台前端 | `index.html:551`、`:880-883` | `if (j.ok)` 判成败；`copyLog()` 无条件提示"已复制" |
| App 更新 | `AppUpdateRepository.kt:100` | `check(written > 0)` 即算下载成功 |
| App 翻译 | `AppViewModel.kt:745-754` | `.isSuccess` 吞掉返回的 false |

建议写进 `.agents/rules/code-and-verification.md`：**"成功"必须由被调用方显式声明，不得由"没抛异常"推定。**

### 5.6 值得肯定（复核确认，非问题）

- **密钥与隐私**：无任何硬编码密钥/令牌；API Key 经 `CloudKeyStore` AES/GCM + AndroidKeyStore 加密落盘；全 `app` 包 `Log.*`/`println`/`printStackTrace` **零命中**（无日志泄漏）；自动更新检查默认关闭，与"离线优先"承诺一致。
