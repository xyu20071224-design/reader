## 3. 三批代码修复

### B1 生词整词高亮（对应 issue 主1 / 补2 / 补7 / 补8）

**根因**：
1. `SavedWord` 只存原型（`headword`），正文里点的 `studied` 存成 `study`；
2. 前端 `markSavedWords` 用 `indexOf` 做纯子串匹配，无词边界、无词形还原。

两者叠加精确复现三种症状：原型是前缀 → 只画一半；原型不是前缀 → 画不上；原型嵌在无关词内 → 画错。

**修复**：
- `Models.kt`：`SavedWord` 新增 `surfaceForms` 字段，JSON 读写 + 老数据回退空列表；
- `VocabularyRepository.kt`：入库累积 `entry.surfaceWord`，同词多形态合并（上限 8）；
- `ReaderScreen.kt`：高亮词表改为 `flatMap { 原型 + 表面形 }`；
- `ReaderController.kt`：去重键与实际注入列表对齐，并统一上限常量；
- `ReaderScripts.kt`：`markSavedWords` 重写为 `\b` 词边界 + 形态展开 + 单次正则扫描，并保留正文原样大小写/变形。

**验证**：项目现有 JS 测试只是 `assertContains` 文本断言，挡不住行为错误。我用 Node 直接执行从 `.kt` 源文件抠出来的纯函数段，抓到了「辅音双写」遗漏（`run` 画不出 `running`，正是 issue 补2 的原样症状），补上后 10 个场景全过。

### B2 长文本整本翻译失败（对应 issue 主2）

**根因（三段放大）**：
1. 数字锚点零容忍：`AiBookTranslator` 要求每个 `\d+` 原样出现在译文，模型把 `1,000` 译成「一千」即判失败；
2. 长度比同样硬失败；
3. 一批失败即中止整本书，且重试无退避。文本越长、批数越多，命中概率越接近 1。

**修复**：
- 校验分两档：硬校验（缺 segments/编号不全/译文空白）任何时候拒绝；软校验（数字锚点/术语/长度比）加 `strict` 开关，首轮拒绝、重试轮放行；
- `translateBook` 逐批容错：单批用尽重试后 `onBatchFailed` 回调 + 用英文原文占位继续跑，整本书不再中止；
- 重试退避：429 → 8s、5xx → 4s、其它 → 800ms（可注入，单测不真睡）；
- `AppViewModel` + 中英文案：汇总「N 段未能翻译，已保留原文，重新生成可补齐」。

**两个关键取舍**：失败批用英文原文占位（不能空串，否则 `xhtmlFor` 滤空后段数错位）；失败批不落检查点，重跑只补失败批。

### B3 数据安全与崩溃兜底

**进度回退（唯一会真实丢用户数据的问题）**：
- `LibraryRepository` 的三个 save 改为**锁内读-改-写**：先读盘上最新记录，只改本方负责的字段，不再用调用方过期快照整份覆盖；
- `writeMetadata` 的 rename 失败回退不再半途直写目标文件（那会留下截断 JSON → 书静默从书架消失）；
- `migrateLegacyMetadata` 逐条容错：一条坏记录不再毁掉整批，也不吞异常。

**章节损坏崩溃**：
- `TtsPlaybackEngine` scope 挂 `CoroutineExceptionHandler { pause() }`，章节文件缺失/损坏导致的 IOException 从「进程崩溃」降级为「暂停」；
- `onReaderPositionChanged` 单独 `runCatching`，跟随失败只放弃这次跟随、不惊动播放；
- `TtsPlaybackService` scope 同样挂 handler，兜底 `stopSelf()`。
