# BUG-036 `Int.MAX_VALUE` 末页哨兵被恢复判据排除，回翻跳到上一章开头

- 严重程度：🟠 中等
- 状态：待修复
- 置信度：高
- 发现日期：2026-09-01
- 来源：GitHub issue #1 正文第 3 条
- 涉及文件：
  - `src/app/src/main/java/com/linguareader/app/ReaderScreen.kt`（`selectChapter` 314–336 行，哨兵在 324 行）
  - `src/app/src/main/java/com/linguareader/app/reader/ReaderScripts.kt`（35、37、244–251 行；多次测量触发点 1049–1055 行）

## 现象

「在阅读到一章末尾进入下一章开头时，如果向回翻会跳到上一章开头」——
期望是回到上一章**最后一页**。

## 根因

Kotlin 侧用 `Int.MAX_VALUE` 当「最后一页」哨兵：

```kotlin
// ReaderScreen.kt:324
initialPage = if (fromEnd) Int.MAX_VALUE else 0
```

JS 侧接住后：

```js
// 35、37 行
let page = Math.max(0, 2147483647);
let restoreTarget = page;
```

关键在 `updateMetrics` 的分页分支：

```js
// 244-249 行
pageCount = Math.max(1, Math.ceil(scroller.scrollWidth / window.innerWidth) - 1);
page = clamp(page, 0, pageCount - 1);
// 「首次测量在字体/图片加载完成前跑，恢复目标不能丢」的救援分支：
if (restoreTarget <= pageCount - 1) page = Math.max(page, restoreTarget);
```

`updateMetrics` 会被跑很多次（字体 ready、300ms 兜底、resize、chrome inset 变化，
见 1027、1030、1049–1055 行）。**首次测量时字体/图片没加载完，`pageCount` 偏小甚至为 1**，
`clamp` 把 `page` 拍成 0；而那条专为「测量变准后恢复」写的救援分支，
判据是 `restoreTarget <= pageCount - 1` —— `Int.MAX_VALUE` **永远不满足**，
救援永不触发，`page` 就永久停在 0 → 上一章开头。

代码自己的注释（246–248 行）写的正是「A restored page must not be lost when the first
measurement runs before fonts/images finish loading」——作者想到了普通页码，
没想到自己的哨兵会被这个判据排除在外。

## 可证伪预测

1. 章节越长/图片越多（首次测量越不准），复现越稳定；
2. 对一个**极短、无图**的章节回翻，可能正常落在末页（首次测量就已准确）；
3. 临时把 324 行的 `Int.MAX_VALUE` 改成一个足够大但小于真实 `pageCount` 的数
   （如 `50`），回翻应能落到第 50 页附近而不是第 0 页——**这条能直接把根因钉死**。

## 修复建议

用显式哨兵替代大数：

```kotlin
// Kotlin 侧
initialPage = if (fromEnd) LAST_PAGE else 0   // LAST_PAGE = -1
```

```js
// JS 侧
const LAST_PAGE = -1;
let restoreTarget = ($initialPage === LAST_PAGE) ? LAST_PAGE : Math.max(0, $initialPage);
let page = (restoreTarget === LAST_PAGE) ? 0 : restoreTarget;
...
// updateMetrics 内：
if (restoreTarget === LAST_PAGE) page = pageCount - 1;
else if (restoreTarget <= pageCount - 1) page = Math.max(page, restoreTarget);
```

注意 `bootstrap` 的复用分支（25–33 行 `__linguaReaderInstalled`）也会拿
`$initialPage` 去调 `window.lrSetPage`，同样要认识新哨兵。

## 回归验证

- `ReaderPageJumpTest.kt`（已存在）可补纯逻辑用例：给定 restoreTarget 与
  逐次增长的 pageCount 序列，断言最终落点是末页。
- **真机**：找一个含插图的长章节，读到末尾 → 进入下一章 → 立刻向回翻 →
  断言落在上一章最后一页；重复 3 次（首次测量的时序有随机性）。
