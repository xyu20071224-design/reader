# BUG-022 语音工作室「随机试听」必崩：`playPreview` 收到 null 按钮

- 严重程度：🟠 中等
- 状态：已修复
- 修复日期：2026-08-19
- 发现日期：2026-08-17
- 涉及文件：`tts-voice-studio/index.html`（`randomPreview` 833–844 行；`playPreview` 679–714 行）

## 现象

后端运行正常、音色列表正常时，点击 Kokoro 或 IndexTTS 区块右上角的
「🎲 随机试听」按钮，控制台抛出：

```text
TypeError: Cannot read properties of null (reading 'classList')
```

音频不会播放。普通音色卡片上的「试听中文 / 试听英文」不受影响。

## 根因

`randomPreview` 选中音色后把 `null` 当作播放按钮传入：

```javascript
// index.html:843
playPreview(engine, v.name, lang, null);
```

而 `playPreview` 无条件把 `btn` 当 DOM 元素使用：

```javascript
// index.html:687
btn.classList.add("playing");
btn.textContent = "合成中…";
btn.setAttribute("aria-busy", "true");
```

`btn === null` 时第一行即抛异常，后续 `fetch("/api/preview")` 不会执行。

## 修复建议

让 `playPreview` 支持无按钮播放：对所有 `btn.*` 操作加 `if (btn)` 守卫
（`playingBtn = btn` 仍可保持 null），例如：

```javascript
if (btn) {
  btn.classList.add("playing");
  btn.textContent = "合成中…";
  btn.setAttribute("aria-busy", "true");
}
playingBtn = btn;
// ...
if (btn) btn.textContent = "播放中…";
```

`resetBtn()` 已经能处理 `playingBtn == null`，无需额外改动。

## 回归验证

1. 启动任一后端并等待 `state == "running"`。
2. 点击「🎲 随机试听」。
3. 预期：控制台无异常，音频开始播放；点击其他试听可正常打断。
