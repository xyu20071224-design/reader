## 现象

1. 保存生词后，正文里**任何包含该字母序列的位置**都会被划线：保存 `app` →
   `apple` 里的 `app` 被标亮；保存 `he` → `the / she / when / there` 全中招。
2. 反过来，保存的是**词典原型**而正文是变形时，只有原型那一段被划线：保存
   `run`，正文 `running` 只有前三个字母有下划线，`ning` 裸露在外。

第 2 点用户报为「划线的生词只画了原型的部分」，与第 1 点是**同一机制的两面**。

## 根因

`markSavedWords` 的命中判定是裸子串匹配，没有词边界校验：

```js
for (const word of active) {
  const index = lower.indexOf(word.toLowerCase());   // 747 行：无边界校验
  if (index >= 0 && (best === null || index < best.index)) {
    best = { index: index, word: word };
  }
}
```

Kotlin 侧术语匹配 `BookGlossary.matchesIn` 早就有 `boundaryOk`
（`ai/AiModels.kt` 496 行起：前后字符为字母/数字且非 CJK 时不算边界），
两端语义不一致。

附带缺陷（同一段代码，建议一并修）：

- **746–751 行取「最早出现」而不是「最长匹配」**：同时存了 `app` 和 `apple` 时，
  `apple` 会被切成 `app` + `le` 两段，高亮边界看起来像截断。
- **724 行 `word.trim().length >= 2`**：单字母生词（`a`、`I`）被静默丢弃，
  用户保存后永远看不到划线，且无任何提示。

## ✅ 修复落地情况（2026-09-01 复核补记）

`5c36f2c` 已把 `markSavedWords` 的裸子串扫描整体换成**整词正则**，本条三项现象与两项
附带缺陷一并解决（当前实现见 `ReaderScripts.kt` 约 780–878 行）：

- 词边界：`buildSavedPattern` 生成 `new RegExp('\\b(' + alt + ')\\b', 'gi')`——`app` 不再画进 `apple`。
- 最长优先：候选按长度倒序（`forms.sort((a,b) => b.length - a.length)`），`apple` 不会被切成 `app` + `le`。
- 变形词：`savedWordVariants` 规则展开 -s/-ed/-ing、CVC 双写、y→ies、词尾 e、-es，
  不规则变化由新增的 `SavedWord.surfaceForms` 兜底（即 BUG-028）。
- 大小写：回填改用 `match[0]` 原文切片（即 BUG-029）。
- 回归用例：`ReaderScriptsTest` 断言脚本含 `savedWordVariants` / `buildSavedPattern`；
  `ModelsTest` 覆盖 `surfaceForms` 序列化与老数据缺字段回退。

## 修复建议

JS 侧复用 Kotlin 端的边界规则，并把「最早匹配」改成「最长匹配优先」：

```js
function isWordChar(ch) {
  if (ch == null) return false;
  if (/[\u3040-\u30FF\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF]/.test(ch)) return false;
  return /[0-9A-Za-zÀ-ÖØ-öø-ÿ]/.test(ch);
}
// 命中后校验：!isWordChar(text[index - 1]) && !isWordChar(text[index + word.length])
```

注意 WebView（minSdk 23）对 `\p{L}` 的支持不完整，用字符类枚举更稳。
候选排序改为 `active.sort((a, b) => b.length - a.length)` 后再取首个过边界的命中。
