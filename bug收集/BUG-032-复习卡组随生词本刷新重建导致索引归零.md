# BUG-032 复习卡组随生词本刷新重建，卡片索引归零 / 待复习数恒为 5

- 严重程度：🟠 中等
- 状态：**已修复（2026-09-02，D3.1）**——见文末「归档」
- 置信度：高（有一个干净的判别实验，见下）
- 发现日期：2026-09-01
- 来源：GitHub issue #1 标题补充第 5、12 条
- 涉及文件：
  - `src/app/src/main/java/com/linguareader/app/ReaderScreen.kt`（231–233、579、729 行）
  - `src/app/src/main/java/com/linguareader/app/ReviewUi.kt`（86 行）
  - `src/app/src/main/java/com/linguareader/app/data/ReviewMode.kt`（47、144、156 行）

## 现象

1. 「快速复习时总是显示有 5 个要复习的单词」——不管实际待复习多少，数字恒为 5；
2. 「快速复习时如果待复习词多于 5 个总是会在前 5 个词之间循环」——永远走不到第 6 个词。

## 根因

三处叠加，链条如下。

### 1）卡组按固定 id 列表取，且取前 N 个

```kotlin
// ReaderScreen.kt:579 与 729（工具栏徽标入口 / 暂停提示入口，两处同款）
reviewDeckIds = dueWords.take(reviewPace.sessionMaxWords).map { it.id }
```

`sessionMaxWords` 的三个默认值（`ReviewMode.kt:47` 标准档、`144` `defaultCustom()`、
`156` JSON 缺省）**都是 5**。卡组一旦定下就是这 5 个 id，复习过也不会被剔除，
所以计数永远是 5（现象 1）。

### 2）卡组是「派生状态」，会随生词本每次刷新重建

```kotlin
// ReaderScreen.kt:231-233
val reviewDeck = remember(savedWords, reviewDeckIds) {
    reviewDeckIds?.let { ids -> savedWords.filter { it.id in ids } }?.takeIf { it.isNotEmpty() }
}
```

复习一个词 → `AppViewModel` 的 `reviewWord`（830 行附近）把新的
`savedWords` 推给 UI（该词的 `level`/`nextReviewAt` 已变）→ `remember` 的 key
`savedWords` 变化 → **重算出一个新的 deck List 实例**。

### 3）卡片索引以 deck 为 key，deck 一变就归零

```kotlin
// ReviewUi.kt:86
var index by rememberSaveable(deck) { mutableIntStateOf(0) }
```

新 deck 实例 → `rememberSaveable` 的 key 变了 → **`index` 重置为 0，卡组从第一张重来**
（现象 2）。

## 判别实验（最有价值的一步）

生词本页面走的是**快照**而不是派生状态：

```kotlin
// VocabularyScreen.kt:75 / 114
var reviewDeck by remember { mutableStateOf<List<SavedWord>?>(null) }
...
reviewDeck = dueWords     // 点击时抓一份，之后不随 words 变化重建
```

**预测：从阅读器工具栏进入快速复习会循环，从生词本页面进入不会。**

如果真机上两个入口表现一致，本假设作废，需要改查 `ReviewUi` 内部的会话推进逻辑。

## 修复建议

1. **卡组快照化**：`ReaderScreen` 也改成点击时抓一份 `List<SavedWord>` 快照
   （与 `VocabularyScreen` 一致），或者继续存 id 但把 deck 的
   `remember` key 收窄为 `reviewDeckIds`，用 `derivedStateOf` 只在 id 列表变化时重建。
   注意 `reviewDeckIds` 用 `rememberSaveable` 是为了旋屏恢复（233 行注释），
   这个能力要保留。
2. **索引不要以整个 deck 为 key**：`ReviewUi.kt:86` 改成
   `rememberSaveable(deckSignature) { ... }`，签名只取 id 列表拼接，
   与词的 `level`/`nextReviewAt` 解耦。
3. **计数改为「剩余」而非「卡组大小」**：显示 `deck.size - index`，
   或在一轮结束后自动用新的 `dueWords` 续下一轮（这条同时消掉现象 1）。

## 回归验证

- 新增 JVM 单测覆盖「deck 签名」纯函数：同 id 不同 `nextReviewAt` 应产出相同签名。
- 真机：存 8 个词并让其全部到期 → 从阅读器进快速复习 → 断言能连续走到第 5 张、
  且计数递减；再从生词本进，行为一致。
## 归档（2026-09-02，D3.1）

**根因确认**：`ReviewUi.ReviewSheet` 把**卡组本身**当 `rememberSaveable` 的键：

```kotlin
var index by rememberSaveable(deck) { mutableIntStateOf(0) }   // deck 是 List<SavedWord>
```

而复习一张卡会改这个词的 `reviewLevel`/`nextReviewAt` → 上游 `savedWords` 更新 →
阅读页那边的 deck 又是 `savedWords.filter { it.id in ids }` **现算**出来的 →
得到一个「不相等」的新列表 → `index`/`completedCount`/`allDone` 全部归零。
于是卡片翻不过去、待复习数看着永远不变。

**修法**：键换成**卡组身份**（有序 id 串）而不是卡组本身 ——
同一次会话里成员不变，它就不变；换一副卡组时才变。

```kotlin
val deckKey = remember(deck) { deck.joinToString("|") { it.id } }
var index by rememberSaveable(deckKey) { mutableIntStateOf(0) }
```

**真机验证**（PKB110，verify 包，4 个待复习）：

| 步骤 | 界面 | 盘上 |
| --- | --- | --- |
| 打开复习 | 第 1 / 4 张 · study | — |
| 评第一张 | **已完成 1 / 4** · app | study reviewCount=1 |
| 评第二张 | **已完成 2 / 4** · run through | study, app 均已复习 |

计数与卡片都在推进，不再归零。

**同源提示**：这与刚修完的「阅读位置」是同一个错误形状 ——
**派生量（卡组）被上游重建，把用户进度（索引）冲掉了**。
参见「重构方案-数据所有权与生命周期.md」证据 10。
