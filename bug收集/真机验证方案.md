## 2. 批次 1：TTS 引擎核心链路（真机手测）

> 云 TTS 需要可用的 Azure/火山/自建服务；系统引擎 & Piper 可离线验证。

### 2.1 BUG-001/002 云 TTS 回退与初始化恢复
1. 听书设置 → 选择云 TTS，填入**错误的 Key/Region**（或断网）。
2. 开始听书。
3. 期望：
   - 不无限重建云引擎、不持续请求、不重复计费日志；
   - 自动回退到系统语音并能朗读；
   - 听书条引擎显示「系统语音（云 TTS 失败）」。
4. 恢复正确配置后能正常重连。

记录：- [ ] 通过　- [ ] 失败（现象：＿＿）

### 2.2 BUG-005 暂停时不继续出声
1. 用云引擎 + 较慢自建服务，切到新章节（首句预合成中）。
2. 立即按暂停。
3. 等待 3~5 秒：
   - 期望：不再出声、听书条保持「已暂停」，不被翻回「播放中」。
4. 再按播放可恢复。

记录：- [ ] 通过　- [ ] 失败

### 2.3 BUG-006/007/015 上一句/下一句
- 快速连按「下一句」多次 → 不重复朗读同一句。
- 在章节开头按「上一句」跨章 → 上一章末句按时出声，不无限等待旧章节预生成。
- 上一章末尾为空白句时 → 不跳回当前章开头，正确朗读上一章最后一个非空白句。

记录：- [ ] 通过　每条：＿＿

### 2.4 BUG-003 外部媒体控制
- 开始听书后，用蓝牙耳机/耳机线控/锁屏媒体卡片：
  - 播放、暂停、上一句、下一句、停止。
- 期望：都能正确控制听书。

记录：- [ ] 通过　- [ ] 失败

### 2.5 BUG-004 Piper 标签
- 选择「本地 Piper / 离线语音」并听书。
- 期望听书条/通知显示「本地 Piper 语音」，而非「系统语音」。

### 2.6 BUG-008 Sherpa 资源清理（压测）

## 4. 批次 3：TTS 服务端 / 语音工作室（运行在电脑侧）

> `tts-server`、`tts-voice-studio` 面向 Windows 运行；手机通过局域网访问 `tts-server`。

### 4.1 BUG-023 动态局域网 IP
- 打开语音工作室，`/api/voices` 返回的 `lan_ip` 应为**自动探测**结果，而不是写死的 `192.168.1.9`。
- 换一个 Wi-Fi 后，手机仍能用返回的 IP 连上服务。

验证命令（电脑侧）：

```bash
curl http://127.0.0.1:8002/api/voices | python -m json.tool | grep lan_ip
```

记录：- [ ] 通过　- [ ] 失败（返回：＿＿）

### 4.2 BUG-024/025 服务端健壮性（自建 TTS 服务）
- POST 非字符串 `voice`/`input` → 返回 **400 JSON**，而非 500：

```bash
curl -s -X POST http://127.0.0.1:8000/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"input":"hello","voice":123}'
# 期望：{"error":"voice 必须是字符串"}  400
```

- 并发首次请求 `/voices` → Kokoro 只加载一次（日志出现一次「模型加载完成」）。

记录：- [ ] 通过　- [ ] 失败

### 4.3 BUG-016/017 进程管理
- 并发点击「启动」多次 → 只拉起一个后端进程，不产生孤儿进程。
- 点击「停止」→ 只停止由工作台启动的进程；`taskkill` 带 `/T`，worker 不残留；不会误杀无关进程。

记录：- [ ] 通过　- [ ] 失败

### 4.4 BUG-018 安全
- 语音工作室默认只绑 `127.0.0.1`（`netstat` 显示监听 127.0.0.1:8002）。
- 若给 `tts-server` 设置 `AUTH_TOKEN`，未带 Token 的请求返回 401。

记录：- [ ] 通过　- [ ] 失败

### 4.5 BUG-022/026 试听前端
- 在语音工作室网页：
  - 随机试听（不崩、能播放）；
  - 连续试听/中途停止/历史重听中断后，浏览器内存不持续增长（blob URL 有释放）。

记录：- [ ] 通过　- [ ] 失败
