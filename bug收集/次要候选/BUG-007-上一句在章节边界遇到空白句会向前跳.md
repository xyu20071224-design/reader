# BUG-007 章节边界按「上一句」且上一章末尾为空白句时，会跳回当前章开头

- 严重程度：🟡 轻微
- 状态：已修复
- 修复日期：2026-08-19
- 发现日期：2026-08-16
- 涉及文件：`src/app/src/main/java/com/linguareader/app/tts/TtsPlaybackEngine.kt`

## 现象

假设上一章的最后一个（或最后几个）句子在提取后是空白（`SentenceSplitter` 过滤后该块
无内容或句末为纯空白），当前正处于本章第一句时按「上一句」：预期跳到上一章可读的
最后一句，实际却**从当前章第一句开始向前朗读**（等效于"重新读当前章"，甚至可能循环）。

## 根因

`previous()`（第 186–210 行）在 `sentenceIndex == 0 && chapterIndex > 0` 时：

```kotlin
scope.launch {
    val previous = chapterLoader(currentBook, targetChapter)
    if (chapterIndex != targetChapter || book !== currentBook) return@launch
    chapter = previous
    sentenceIndex = (previous.sentenceCount - 1).coerceAtLeast(0)
    speakCurrent()
}
```

而 `speakCurrent()`（第 456–494 行）遇到空白句会：

```kotlin
if (text.isBlank()) {
    sentenceIndex++
    loadAndSpeakCurrent()
    return
}
```

若 `previous.sentenceCount - 1` 处的句子是空白，`sentenceIndex++` 后等于
`sentenceCount`，`loadAndSpeakCurrent`（第 394–402 行）判定"本句越界"→
`chapterIndex++`（即回到用户原来所在的章）→ 从该章第 0 句开始朗读。

方向性错误：用户按"上一句"，播放却前进了。

## 修复建议

跳章回退时跳过空白句并保持方向一致。例如在 `previous()` 中向前搜索最后一个非空白句：

```kotlin
var idx = (previous.sentenceCount - 1).coerceAtLeast(0)
while (idx > 0 && previous.sentences[idx].isBlank()) idx--
sentenceIndex = idx
speakCurrent()
```

若整章全空白，则应继续向前一章，而不是交给 `loadAndSpeakCurrent` 的"越界推进"逻辑
（那是为向后播放设计的）。

## 回归验证

- 单测：构造上一章末尾含空白句的章节，从本章第 0 句按 `previous()`，
  断言朗读的是上一章最后一个非空白句，且 `chapterIndex` 未回跳。
