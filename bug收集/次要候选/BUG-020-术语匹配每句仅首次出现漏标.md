# BUG-020 术语匹配每个句子只返回第一次出现，重复术语在整句翻译中漏标

- 严重程度：🟡 轻微
- 状态：已修复
- 修复日期：2026-08-19
- 发现日期：2026-08-17
- 涉及文件：`src/app/src/main/java/com/linguareader/app/ai/AiModels.kt`（`matchesIn` 213–243 行）

## 现象

一句话里同一个词表术语出现两次（如 "Harry Potter ... Harry Potter"）时，Azure 整句翻译
的动态词典标记只作用于**第一次**出现处，第二次出现仍按普通词翻译，译文前后不一致。

## 根因

`matchesIn` 的 `while (true)` 循环一旦找到第一个「未被占用且过词边界」的匹配，
立即 `return@mapNotNull`：

```kotlin
while (true) {
    val index = lower.indexOf(termLower, searchFrom)
    if (index < 0) break
    ...
    if (occupied.none { ... } && boundaryOk(sentence, index, end)) {
        occupied += range
        return@mapNotNull GlossaryMatch(...)   // 231 行：首个命中即返回
    }
    searchFrom = index + 1                     // 仅推进「被否决」的匹配
}
```

`searchFrom` 的推进只对「被否决（重叠或越界）」的匹配生效，正常命中的后续重复出现
永远不会被收集。而下游 `AzureSentenceTranslator.markupSentence` 本身支持多个匹配
（逐个替换），管线却没收到它们，能力被上游截断。

## 修复建议

命中后不返回，继续 `searchFrom = index + 1` 收集后续非重叠匹配，例如改为
`buildList` 累加；保持 `occupied` 去重与 longest-first 排序不变。

## 回归验证

- 单测：`Glossary(term="Harry Potter").matchesIn("Harry Potter met Harry Potter.")`
  应返回 2 个匹配，start 分别为 0 和 17（示例）。
