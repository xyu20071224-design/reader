# BUG-006 `loadAndSpeakCurrent` 缺少过期保护，连按「下一句」导致同一句重复朗读

- 严重程度：🟡 轻微
- 状态：已修复
- 修复日期：2026-08-19
- 发现日期：2026-08-16
- 涉及文件：`src/app/src/main/java/com/linguareader/app/tts/TtsPlaybackEngine.kt`

## 现象

系统语音引擎下，快速连按两下「下一句」（尤其是章节加载较慢时），当前这一句会被
**完整读两遍**，然后才跳到下一句。

## 根因

`next()` 每次都会 `sentenceIndex++` 并同步触发 `loadAndSpeakCurrent()`（第 178–184 行），
而 `loadAndSpeakCurrent()`（第 391–453 行）把章节加载放进**不带任何过期保护**的协程：

```kotlin
scope.launch {
    val loadedChapter = chapterLoader(currentBook, chapterIndex)
    chapter = loadedChapter
    ...
    speakCurrent()
}
```

连按两次后两个协程先后完成，各执行一次 `speakCurrent()` → `speakNow()`。两次 speak 的
utteranceId 只差 attempt 段（`speakAttempt` 在 `speakNow` 里自增），系统 TTS 的
`QUEUE_ADD` 会把两句都排入队列播放：旧 attempt 的 `onDone` 因 id 不匹配被引擎忽略
（不会多跳一句），但**声音重复**了。

对比：`previous()` 第 196–202 行专门为此加了过期保护：

```kotlin
val targetChapter = chapterIndex
scope.launch {
    val previous = chapterLoader(currentBook, targetChapter)
    if (chapterIndex != targetChapter || book !== currentBook) return@launch
    ...
}
```

`loadAndSpeakCurrent` 却没有同等保护，属于同一缺陷在不同路径上的遗漏。

## 修复建议

在 `loadAndSpeakCurrent` 启动协程前捕获目标（或引入单调递增的 load generation），
加载完成后校验：

```kotlin
val targetChapter = chapterIndex
val targetSentence = sentenceIndex
scope.launch {
    val loadedChapter = chapterLoader(currentBook, targetChapter)
    if (book !== currentBook || chapterIndex != targetChapter) return@launch
    // 若在加载期间用户又切了句，交给最新的那次加载负责朗读
    if (sentenceIndex != targetSentence && chapterIndex == targetChapter) return@launch
    ...
}
```

注意需与 `sentenceIndex >= sentenceCount` 的跨章推进逻辑协同，避免吞掉合法推进。

## 回归验证

- 单测：让 `chapterLoader` 挂起，期间连续调用两次 `next()`，推进虚拟时间后断言
  每个句子只被 speak 一次。
