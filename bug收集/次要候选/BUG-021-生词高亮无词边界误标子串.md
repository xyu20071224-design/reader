# BUG-021 生词高亮无词边界，短词被误标进不相关单词

- 严重程度：🟡 轻微
- 状态：❌ **未修复（main 线）** — 原记「已修复」系随文档从 legacy 线整批导入，属误标，
  2026-08-29 取证订正，详见文末「状态订正」
- 修复日期：main 线尚无；legacy 线为 2026-08-19（`b784acd`，未移植）
- 发现日期：2026-08-17
- 涉及文件：`src/app/src/main/java/com/linguareader/app/reader/ReaderScripts.kt`
  （`markSavedWords`，当前 main 为 721–776 行，裸匹配在 **747 行**）

## 现象

保存短生词后阅读器会高亮到无关单词的子串：保存 "he" 会把 "the / she / when / there"
里的 "he" 全部标亮；保存 "as" 误标 "has / was / ask / class"；保存 "is" 误标
"this / his"。

## 根因

JS 侧 `markSavedWords` 是裸子串匹配，没有词边界判断：

```js
for (const word of active) {
  const index = lower.indexOf(word.toLowerCase());   // 无边界校验
  ...
}
```

而 Kotlin 侧术语匹配 `BookGlossary.matchesIn` 有 `boundaryOk`（`AiModels.kt` 245–252 行：
前后字符为字母/数字且非 CJK 时不算边界）。两端对「词边界」的语义不一致，阅读器高亮
因此出现大量误报。

## 修复建议

JS 侧复用同一套边界规则。例如先计算前后字符，再决定是否接受该命中：

```js
function isWordChar(ch) {
  return ch != null && /[\p{L}\p{N}]/u.test(ch) && !/[\u3040-\u30FF\u3400-\u4DBF\u4E00-\u9FFF\uF900-\uFAFF]/.test(ch);
}
const before = text[index - 1], after = text[index + word.length];
const boundaryOk = !isWordChar(before) && !isWordChar(after);
```

（注意 WebView 对 `\p{L}` 的支持情况，必要时退回字符类集合枚举。）

## 回归验证

- 保存 "he" 后打开含 "the she when" 的章节，断言这些词内的 "he" 不被高亮；
  独立的 "he" 正常高亮。
- 属 WebView 注入 JS 的渲染行为，单测覆盖不到，**必须真机/模拟器实测**（见 AGENTS.md 验证纪律）。

function isWordChar(ch) {
  if (ch === undefined || ch === null || ch === '') return false;
  if (/[\s\p{P}]/u.test(ch)) return false;
  // Match the Kotlin rule: Latin letters/digits continue a word;
  // CJK characters are treated as boundaries.
  return /[\p{L}\p{N}]/u.test(ch) || /[A-Za-z0-9]/.test(ch);
}
