# BUG-009 停止操作与异步启动的竞态：已停止的播放会被复活

- 严重程度：🟡 轻微
- 状态：已修复
- 修复日期：2026-08-19
- 发现日期：2026-08-16
- 涉及文件：`src/app/src/main/java/com/linguareader/app/tts/TtsPlaybackService.kt`

## 现象

从「点句子开始听书」的路径启动时，Service 先在 IO 线程提取章节、定位句子索引，再调用
`engine.startPlayback`。若用户在这个毫秒级窗口内点了停止（或退出了书籍），几秒后
听书**自己又开始播放**，需要再按一次停止。

## 根因

`handlePlay`（第 170–195 行）：

```kotlin
sentenceText.isNotEmpty() -> scope.launch {
    val chapter = withContext(Dispatchers.IO) { extractor.chapter(newBook, requestedChapter) }
    val index = chapter.sentences.indexOfFirst { it == sentenceText }.takeIf { it >= 0 } ?: 0
    engine.startPlayback(newBook, requestedChapter, index)
}
```

`scope.launch` 里没有任何"会话已被停止/替换"的校验。期间若 `ACTION_STOP` 到达，
`stopPlayback()` → `engine.stop()` 会在主线程执行并清空状态，但挂起的协程恢复后照常
调用 `startPlayback`，播放复活。同理，用户在窗口内启动了另一本书，旧书协程恢复后
会覆盖新书的会话。

## 修复建议

1. 给 Service 增加会话代次（generation）计数：`stopPlayback()` 与每次 `handlePlay`
   启动时递增；协程恢复后校验代次是否仍等于启动时的值：

   ```kotlin
   val generation = ++playGeneration
   scope.launch {
       ...
       if (generation != playGeneration) return@launch
       engine.startPlayback(newBook, requestedChapter, index)
   }
   ```

2. 或把取消语义显式化：为每次 play 请求持有 `Job`，`stopPlayback()` 时先 `job.cancel()`。

## 回归验证

- 单测/集成：触发 `handlePlay` 的异步路径后立即发 ACTION_STOP，断言服务最终保持停止
  （状态为初始态、无前台通知）。
