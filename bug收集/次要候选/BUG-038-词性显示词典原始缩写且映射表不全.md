# BUG-038 词性直接显示词典原始缩写（adj 显示成 a），且映射表不全

- 严重程度：🟡 轻微
- 状态：待修复
- 置信度：高
- 发现日期：2026-09-01
- 来源：GitHub issue #1 标题补充第 10 条
- 涉及文件：`src/app/src/main/java/com/linguareader/app/data/ContextAnalyzer.kt`
  （`senses` 201–217 行，`sensePartOfSpeech` 231–241 行，`PartOfSpeech` 7–11 行）

## 现象

「词性标注不完全，如将 adj 标为 a」。

## 根因

### 1）显示的是词典原文，不是应用的标注

```kotlin
// 201-214 行
.map { line ->
    val partOfSpeech = sensePartOfSpeech(line)
    DictionarySense(
        text = line,                    // ← 直接用 ECDICT 原始行，形如 "a. 美丽的"
        partOfSpeech = partOfSpeech,
        contextPreferred = inferred != PartOfSpeech.UNKNOWN && partOfSpeech == inferred
    )
}
```

解析出来的 `PartOfSpeech` 枚举**只被用于排序**（`contextPreferred`，216 行），
它自带的本地化标签（`R.string.pos_adjective` 等，7–11 行）**从未被渲染**。
用户看到的 `a.` 是词典自己的缩写风格，不是应用标的。

### 2）映射表覆盖不全

```kotlin
// 231-241 行，只认这些：
n. / n␠ / vt. / vi. / v. / v␠ / a. / adj. / ad. / adv.
```

**缺 `prep.` / `conj.` / `pron.` / `int.` / `num.` / `art.` / `aux.` / `abbr.`**，
这些全部落进 `UNKNOWN`，既不显示词性也不参与语境排序——这就是「标注不完全」。

## 修复建议

1. 扩充 `PartOfSpeech` 枚举与 `sensePartOfSpeech` 的 marker 表，覆盖上述 8 类
   （新增枚举项要同步在 `values/strings.xml` 与 `values-en/strings.xml` **两边**
   加 `pos_*` 文案，项目有过 strings.xml 并发丢 key 的事故，改完跑
   `StringResourcesTest.kt` 核对两语言条目数一致）。
2. 渲染时把行首的原始 marker 剥掉，改用枚举的本地化标签作为独立的小标签
   （`ReaderScreen.kt:1637` 附近展示 `entry.senses`），
   这样 `a.` 会显示成「形容词」/`adj.`，与用户预期一致。
3. `DictionarySense` 建议增加 `cleanText`（剥掉 marker 的释义正文）字段，
   避免 UI 层重复做字符串处理——BUG-039 的候选词提取也能复用它。

## 回归验证

- `data/ContextAnalyzerTest.kt` 增加参数化用例：8 类 marker 各断言映射正确。
- `StringResourcesTest.kt` 应继续通过（zh / en 条目数一致）。
