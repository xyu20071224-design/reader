# BUG-034 听书时手动翻页，无条件把朗读位置拉回本页第一句

- 严重程度：🟡 轻微（**行为符合现有代码意图，属产品决策争议**）
- 状态：待决策
- 置信度：高（机制确定），但「是否算 bug」需产品判断
- 发现日期：2026-09-01
- 来源：GitHub issue #1 正文第 5 条
- 涉及文件：`src/app/src/main/java/com/linguareader/app/ReaderScreen.kt`
  （`reportTtsPositionDelayed` 344–354 行，触发点 490–503 行）

## 现象

「听书功能下如果手动翻页会造成自动跳到当前页的第一句」。

## 根因

不是缺陷，是**当前设计的字面行为**：

```kotlin
// 490-503 行：onPageChanged
if (ttsForThisBook && ttsState.isPlaying) {
    reportTtsPositionDelayed()
}

// 344-354 行
fun reportTtsPositionDelayed() {
    ttsPositionReportJob?.cancel()
    ttsPositionReportJob = scope.launch {
        delay(350)
        controller.firstVisibleBlock { block ->
            if (block != null) {
                TtsPlaybackController.onReaderPositionChanged(book.id, chapterIndex, block)
            }
        }
    }
}
```

翻页 350ms 后取**首个可见块**回报给播放引擎，引擎据此重定位——
意图是「手动翻页后把朗读拉到你正在看的地方」，代价是**丢掉句内位置**，
且在「只是往前翻一页确认一下上文」的场景里显得很粗暴。

## 讨论

值得注意的是它与 OBS-06（分页模式禁止自动翻页，见「观察项-未定级.md」）互为镜像：
因为**引擎不能带着页面走**，才需要**页面带着引擎走**。
如果 OBS-06（分页跟随）实现了，这条的策略也要一起重新设计，
否则两个方向的同步会打架——正是 2026-08-23 真机事故（章末死循环）的成因结构。

## 修复建议（择一，需产品定调）

1. **保守**：仅当「当前朗读句已完全不在视口内」时才重定位；否则保持不动。
   需要 `ReaderScripts` 提供一个「某块是否可见」的查询（`ttsBlocks` 相关代码已有基础）。
2. **显式**：翻页后不自动跳，而在听书条上给一个「从这里继续」按钮，把选择权交给用户。
3. **维持现状**：在听书设置里加开关，默认保持当前行为。

## 回归验证

- **必须真机**。步骤：播放中向前翻 1 页 → 断言朗读**不中断、不回退**；
  连续向前翻 5 页（当前句已远离视口）→ 断言按所选策略行为一致。
- 与 BUG-007/BUG-015（跨章「上一句」）一起回归，避免重定位与跨章逻辑互相踩。
