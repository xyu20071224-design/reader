## OBS-01 LocalGlossaryTranslator：句首大写普通词混入"专名/术语"档案

- 涉及文件：`src/app/src/main/java/com/linguareader/app/ai/LocalGlossaryTranslator.kt`（第 37–40 行）
- 现象：只要单词**首字母大写**、整书出现 ≥2 次且分布在 ≥2 章，就会被收进语境档案。
  句首的 "The / He / It / She" 等高频词必然满足条件，会以高词频占据
  `take(60)` 名额（词频排序靠前），把真正的专名挤出去；术语表 UI 里也会出现
  "The（本书出现 87 次）" 这类无意义条目。
- 建议：加入句首大写词与"句中大写词"的区分（仅句中大写才算专名候选），
  或引入常见功能词黑名单。

## OBS-02 tts-server `detect_lang`：纯数字/标点文本误判为中文

- 涉及文件：`tts-server/server.py`（第 120–124 行）
- 现象：`detect_lang` 用 `cjk >= latin` 判定；对 "123."、"—"、纯空格外的标点句，
  cjk 与 latin 均为 0，条件成立 → 判为中文音色朗读。
- 影响：仅涉及无字母无汉字的句子，听感问题；自建服务器用户会遇到。

## OBS-03 TtsPlaybackEngine `fallbackActive` 字段是死代码

- 涉及文件：`src/app/src/main/java/com/linguareader/app/tts/TtsPlaybackEngine.kt`（第 79 行等）
- 现象：字段在 `startPlayback`/`startStandby`/`reconfigure`/`stop` 中被反复赋 false，
  但**从未被赋 true**，也从未被读取。`fallbackToSystemTts()` 里没有
  `fallbackActive = true`，疑似回退状态标记的半成品（可能原意用于
  回退期间跳过再次回退/云引擎重选判断）。
- 建议：删除死字段，或在 `fallbackToSystemTts` 正确赋值并用于状态展示。

## OBS-04 CloudTtsSynthesizer：全书缓存进行中点击句子朗读，可能同句重复合成计费

- 涉及文件：`src/app/src/main/java/com/linguareader/app/tts/CloudTtsSynthesizer.kt`
  （`waitForFileOrSynthesize` 第 239–260 行）
- 现象：`speak()` 等待文件时只感知 `prepareJob`（章节预合成），不感知
  `bookPrepareJob`（全书缓存）。全书缓存进行中播放某句：25 秒 deadline 后文件
  尚未生成（缓存队列还没轮到），代码不会等 `bookPrepareJob`，而是直接
  `backend.synthesize` 再合成一次 → 云服务同句重复计费（`inflightFiles` 去重只
  覆盖 `generateOne` 路径，覆盖不到这里）。
- 建议：等待循环中同时观察 `bookPrepareJob?.isActive`，或把直接合成路径也纳入
  `inflightFiles` 登记。

## OBS-05 ReaderScreen：整句翻译失败静默吞掉，无任何提示

- 涉及文件：`src/app/src/main/java/com/linguareader/app/ReaderScreen.kt`（第 726–735 行）
- 现象：`sentenceTranslation = runCatching { ... }.getOrNull()`——网络失败、Key 错误、
  BUG-011 的 XML 非法等所有错误都被吞掉，面板上只显示"没翻译出来"，用户无从判断
  是未配置、网络问题还是术语表导致。
- 建议：失败时把 `Throwable.message` 展示在翻译区域（如"翻译失败：HTTP 401"）。
