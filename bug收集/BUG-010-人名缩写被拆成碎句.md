# BUG-010 人名缩写（J. K. Rowling）被 SentenceSplitter 拆成碎句

- 严重程度：🟠 中等
- 状态：已修复
- 修复日期：2026-08-19
- 发现日期：2026-08-16
- 涉及文件：`src/app/src/main/java/com/linguareader/app/tts/SentenceSplitter.kt`
- 验证方式：✅ 已用脚本按原逻辑逐行复现（见「证据」节）

## 现象

英文书中带空格分隔的姓名缩写会被拆成多个"句子"：

- `"J. K. Rowling walked in."` → `["J.", "K.", "Rowling walked in."]`
- `"George R. R. Martin wrote the book."` → `["George R.", "R.", "Martin wrote the book."]`

听书时人名会被拆成 3 段分别朗读（"J."、"K."、剩下一句），当前句高亮也随之
在碎句间跳动。**"J. K. Rowling"、"George R. R. Martin"、"T. S. Eliot" 这类写法
在英文文学作品中极其常见**，整章听书会频繁出现此问题。

## 根因

`initials` 正则（第 17 行）要求缩写点号**连续**出现：

```kotlin
private val initials = Regex("""\b(?:[A-Za-z]\.){2,}""")
```

`{2,}` 要求 `[A-Za-z]\.` 至少重复两次且中间不能有任何字符。对 `"J. K."`：
引擎在 `J` 处匹配到 `J.` 后，第二个 `[A-Za-z]` 遇到空格即失败；从 `K` 处重试，
`K.` 之后又只剩一个点号组，`{2,}` 依旧失败。于是 `J` 和 `K` 后面的点号
**全部不在 `protectedPeriods` 里**。

随后主循环（第 30–67 行）处理 `J` 后面的 `.` 时：

```kotlin
val shouldSplit = when {
    ...
    else -> text[end] == ' '   // 点号后是空格 → 判定为句尾，切分
}
```

点号后是空格即被当作句尾，句子在 `J.` 处被切开；`K.` 同理再切一次。
（对比：`Mr.`/`Dr.` 等靠 `abbreviation` 正则保护，`"U.S."` 这类连续缩写靠
`initials` 保护，唯独空格分隔的缩写两边都够不着。）

## 修复建议

把空格分隔的缩写也纳入保护，例如新增正则并保护其内部点号：

```kotlin
private val spacedInitials = Regex("""\b[A-Za-z]\.(?:\s+[A-Za-z]\.)+\b""")
```

在 `protectedPeriods` 中把该模式命中的所有 `.` 都加入保护集（中间点号必保护；
末尾点号按现行 `initials` 的规则——后跟小写字母才保护）。并补充单测：

- `"J. K. Rowling walked in."` 应切为 1 句；
- `"Mr. Smith came at noon."`、`"in the U.S. Next year it changed."` 保持现有行为。

## 证据（按原逻辑的 1:1 复现输出）

```
'J. K. Rowling walked in.'        -> ['J.', 'K.', 'Rowling walked in.']
'George R. R. Martin wrote the book.' -> ['George R.', 'R.', 'Martin wrote the book.']
'Mr. Smith came at noon.'         -> ['Mr. Smith came at noon.']          # 对照：正常
'in the U.S. Next year it changed.' -> ['in the U.S.', 'Next year it changed.']  # 对照：正常
```
