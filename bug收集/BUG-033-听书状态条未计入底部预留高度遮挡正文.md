# BUG-033 听书状态条未计入底部预留高度，浮在正文上造成遮挡

- 严重程度：🟠 中等
- 状态：待修复
- 置信度：高
- 发现日期：2026-09-01
- 来源：GitHub issue #1 正文第 4 条
- 涉及文件：`src/app/src/main/java/com/linguareader/app/ReaderScreen.kt`
  （底栏测量 623–628 行，听书条 697–716 行）、
  `src/app/src/main/java/com/linguareader/app/reader/ReaderScripts.kt`（81、48–49 行）

## 现象

「听书功能开启时总会有一个听书的状态条，造成对文本的遮挡」。

## 根因

阅读器把「Compose 外壳占了多少高度」通过 `--lr-chrome-bottom` 告诉 WebView，
让正文自己让位。但**只有底部翻页栏被测量了**：

```kotlin
// 623-628 行：底部翻页 Row
Modifier.align(Alignment.BottomCenter)
    .fillMaxWidth()
    .onSizeChanged { size ->
        if (size.height > 0) chromeBottomPx = size.height / density
    }
```

而听书条是**另一个独立浮层**，既没有参与测量，又用了硬编码偏移：

```kotlin
// 697-703 行
AnimatedVisibility(visible = ttsForThisBook, modifier = Modifier.align(Alignment.BottomCenter)) {
    ListeningBar(
        state = ttsState,
        modifier = Modifier.padding(bottom = 62.dp),   // 魔数
        ...
```

它的高度从未进入 `chromeBottomPx` → WebView 不知道要留位 → 直接盖在正文上。

顺带：`62.dp` 是对底栏高度的**猜测值**，而底栏高度实际是实测的
（`chromeBottomPx`，还会随导航栏 inset 变化）。项目里已有「用实测自校准」的先例
（`ReaderScripts.kt:200-208` 处理正文底缘被底栏盖住时的注释），这里应保持一致。

## 可证伪预测

1. 关闭听书 → 正文最后一行完整可见；开启听书 → 最后 1–2 行被状态条盖住；
2. 在系统导航栏样式不同的设备/模式（手势 vs 三键）上，遮挡程度不同
   （因为 62.dp 与真实底栏高度的偏差变了）。

## 修复建议

1. 给 `ListeningBar` 的容器加 `onSizeChanged`，把高度记为 `listeningBarPx`；
2. 传给 `EpubPage` 的值改为 `chromeBottomPx + listeningBarPx`
   （`ReaderScreen.kt:474`），`ttsForThisBook == false` 时自动退化为原值；
3. 把 `padding(bottom = 62.dp)` 换成 `padding(bottom = chromeBottomPx.dp)`，消掉魔数；
4. `ReaderScripts` 侧无需改动——`applyChromeInsets`（1015–1028 行）已经支持运行时更新，
   并在 30ms 后重新测量。

## 回归验证

- **必须真机**（WebView 布局 + 系统 inset，单测覆盖不到）。
- 分页模式与滚动模式各验一次：开启听书后正文末行不被遮挡，关闭后不留空白。
- 在手势导航与三键导航两种模式下各截一张图，进 `验证截图/`。
