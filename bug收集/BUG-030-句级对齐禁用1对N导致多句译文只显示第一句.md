# BUG-030 句级对齐禁用 1:N，一句英文译成多句中文时只保留第一句

- 严重程度：🟠 中等
- 状态：待修复
- 置信度：高（算法层面可直接判定）
- 发现日期：2026-09-01
- 来源：GitHub issue #1 标题补充第 1、3、4 条
- 涉及文件：`src/app/src/main/java/com/linguareader/app/translation/TranslationAligner.kt`
  （调用点 90 行，DP 走法 338–353 行，降级分支 92–102 行）

## 现象

1. 「对照当一句英文句子被译成好几句时只会显示第一句」；
2. 「对照存在段落对上了但是句子没对上的问题」；
3. 「出现了对照时位于 A 句后的 B 句返回 A 句意思的问题」（错位）。

## 根因

段落级对齐允许合并，句子级**显式关掉了合并**：

```kotlin
// 77 行：段落级
for (paragraphPair in alignSpans(enSpans, zhSpans, allowMerge = true)) {
// 90 行：句子级
else alignSpans(enSentenceSpans, zhSentenceSpans, allowMerge = false)
```

而 `alignSpans` 里 2:1 与 1:2 两种走法**整体被 `allowMerge` 包住**：

```kotlin
// 338-353 行
if (allowMerge) {
    // MOVE_TWO_ONE : prev2[j-1] + pairCost(a[i-2], a[i-1], b[j-1], null)
    // MOVE_ONE_TWO : prev1[j-2] + pairCost(a[i-1], null, b[j-2], b[j-1])
}
```

于是句级 DP **只剩 1:1 和跳过（SKIP_A / SKIP_B）两种走法**。

中译英文小说时「一句拆成两句」极其常见（长定语从句、分号句）。DP 无法表达 1:2，
只能把第二句中文 `MOVE_SKIP_B` **丢掉** → 用户只看到第一句译文（现象 1）。
跳过会让后续配对整体漂移 → 出现「B 句返回 A 句意思」（现象 3）。
段落 DP 成功但句级 DP 退化到空结果时，走 92–102 行的段落降级分支，
落库的 `enSentence`/`zhSentence` 都是空串 → 「段落对上了句子没对上」（现象 2）。

附带：`join`（395–397 行）合并多句时用**空格**拼接，中文合并结果会出现
「他说。 她笑了。」这种夹空格的译文。

## 可证伪预测

1. 找一段「一句英文 → 两句中文」的原文，点击该英文句 → 只显示前半句译文；
2. 同段落里该句**之后**的句子，点击后返回的是前一句的译文或整段兜底；
3. 把 90 行改成 `allowMerge = true` 重新对齐同一本书 → 现象 1、2 同时消失。

第 3 条是决定性实验，改一个布尔值即可验证。

## 修复建议

**最小改动**：句级放开 1:2（英文 1 : 中文 N），保留 2:1 关闭。
中译拆句远多于并句，而放开 2:1 会引入「两句英文共享一条译文」的新歧义。
建议把 `allowMerge: Boolean` 拆成 `allowMergeA: Boolean` / `allowMergeB: Boolean`
两个开关，句级传 `(false, true)`。

同时把 `join` 对中文侧的拼接分隔符改为空串（英文侧保留空格）。

**⚠️ 数据迁移**：改对齐器后，**已导入书籍的对齐档案是旧结果**，不重算不会变好。
需要给档案加版本号（`translation/TranslationModels.kt` 的落盘结构），
启动时发现版本落后就懒重建，或明确告知用户需重新导入。这部分工作量可能大于算法本身，
排期时必须算进去。
