# BUG-035 进入滑动模式时先置位后取值，阅读进度归零跳回章首

- 严重程度：🟠 中等
- 状态：待修复
- 置信度：**很高**（同文件内有写法正确的对照函数，可判定为笔误）
- 发现日期：2026-09-01
- 来源：GitHub issue #1 标题补充第 6 条
- 涉及文件：`src/app/src/main/java/com/linguareader/app/reader/ReaderScripts.kt`
  （`enterScrollMode` 310–318 行，`currentRatio` 254–257 行，
  对照组 `exitScrollMode` 320–332 行）

## 现象

「进入滑动状态时丢失进度自动翻到章首」。

## 根因

```js
// 310-318 行
function enterScrollMode(ratio, count) {
  if (scrollMode) return;
  scrollMode = true;                                      // ← 先置位
  scrollRatio = ratio == null ? currentRatio() : clamp(Number(ratio) || 0, 0, 1);
  ...
  syncScroll();
}
```

而 `currentRatio()` 的第一句就是按 `scrollMode` 分流：

```js
// 254-257 行
function currentRatio() {
  if (scrollMode) return currentScrollRatio();            // ← 已经是 true 了
  return pageCount > 1 ? page / (pageCount - 1) : 0;      // ← 本来该走这里
}
```

调用发生时**布局还是分页布局**（`applyScrollLayout()` 在下一行才执行，
分页布局下 `overflow-y: hidden`、`scrollTop` 恒为 0），
所以 `currentScrollRatio()` 返回 **0** → `scrollRatio = 0` → `syncScroll()`
把 `scrollTop` 设成 0 → **跳到章首**。

**铁证**：同文件的 `exitScrollMode()` 顺序是反的、正确的：

```js
// 320-324 行
function exitScrollMode() {
  if (!scrollMode) return;
  const ratio = currentScrollRatio();   // ← 先取值
  scrollMode = false;                   // ← 后置位
  scrollRatio = ratio;
```

两个函数写法不对称，说明这是笔误而非设计。

## 可证伪预测

**从第 1 页进入滑动模式不会有感**（ratio 本来就是 0），
**从第 10 页进入必然跳章首**。这个「只在非首页复现」的特征是本假设的签名。

如果在第 1 页也丢进度，说明另有原因（那要查 `applyScrollLayout` 后的重测量路径）。

## 修复建议

三行：

```js
function enterScrollMode(ratio, count) {
  if (scrollMode) return;
  const resolved = ratio == null ? currentRatio() : clamp(Number(ratio) || 0, 0, 1);
  scrollMode = true;
  scrollRatio = resolved;
  ...
```

注意 `bootstrap` 里的另一处调用（26–27 行）传的是显式 `ratio`，走的是 `clamp` 分支，
不受影响；受影响的只有拖拽手势那一处（615 行 `enterScrollMode(null, null)`）。

## 回归验证

- **必须真机**（手势 + WebView 布局）。
- 步骤：分页模式翻到某章第 10 页 → 慢速竖向拖拽进入滑动模式 →
  断言视口停在原位置附近，底部进度文案（647–655 行）显示的百分比与翻页时相当。
- 顺带回归 `exitScrollMode`：从滑动模式点「分页」按钮回到分页模式，位置同样不应跳。
