## 0. 结论速览（三句话）

1. 本仓库的构建目标只有 **3 个**：`:app`（Android）、`:shared`（纯 JVM 库）、`:desktopApp`（Compose Desktop JVM）。
2. **iOS / Web 构建目标、目录、依赖、CI 任务、条件编译分支：全部不存在**（下节给了负证据）。「先把 iOS/Web 从主线移除」在现状下**没有可移除的对象**。
3. 与「Windows / Linux / macOS 三平台」冲突的不是 iOS/Web，而是 **Android（`:app`）** —— 它是现存的主力产品端。这条必须你确认（见问题 Q1）。

### 桌面打包配置（三平台交付的关键缺口）

| 项 | 现状 | 影响 |
| --- | --- | --- |
| 目标格式 | **只声明了 `TargetFormat.AppImage`**（`src/desktopApp/build.gradle.kts:51`） | AppImage 是 **Linux** 格式；Windows 需 Msi/Exe、macOS 需 Dmg/Pkg |
| 运行时 | `compose.desktop.currentOs`（`src/desktopApp/build.gradle.kts:20`） | 只拉**当前构建机**的运行时 |
| 构建入口 | Linux `toolchain/build.sh`、Windows `toolchain/build.ps1`；**无 macOS 脚本** | macOS 无入口 |
| jpackage 特性 | 只能为**宿主 OS** 打包 | Windows/macOS 产物必须在对应 OS 或对应 CI runner 上构建 |

**实测（本机 Linux）**：`:desktopApp:packageAppImage` 报 BUILD SUCCESSFUL，但只产出 app-image 目录 `build/compose/binaries/main/app/LinguaReader/`（`bin/LinguaReader` 为 ELF），**全树无 `.AppImage` 单文件**；日志 `build/compose/logs/packageAppImage/` 内容为 `Input length = 1`（被 Gradle 吞掉）。

## 2. iOS / Web 存在性核查（负证据）

| 检索项 | 命令 | 结果 |
| --- | --- | --- |
| Gradle 子项目 | `grep -nE 'include\(' src/settings.gradle.kts` | 只有 `:app` / `:shared` / `:desktopApp` |
| KMP / js / wasm 插件与 target | `grep -rnE 'multiplatform|kotlin\("js"\)|kotlin\("wasm|iosArm64|iosX64|jsMain|iosMain' src/ --include='*.kts' --include='*.kt'` | **无** |
| Xcode / Swift / Web 入口文件 | `find . -maxdepth 5 \( -name '*.xcodeproj' -o -name '*.pbxproj' -o -name '*.swift' -o -name 'Info.plist' -o -name 'vite.config.*' -o -name 'next.config.*' -o -name 'webpack.config.*' \)` | **无**（仅 `tools/dsh-voice-console/package.json` 是本机工具，非本项目构建目标） |
| 根 `package.json` / `libs.versions.toml` | `ls` | 二者都**不存在** |
| CI 平台 runner | `grep -nE 'runs-on:' .github/workflows/ci.yml` | 两处都是 `ubuntu-latest`，**无 windows/macos，也无 iOS/Web job** |
| Gradle 可用任务 | `./toolchain/build.sh tasks --all \| grep -iE 'ios|wasm|jsBrowser|webpack'` | **无命中** |
| 条件编译分支 | `grep -rnE 'expect fun|expect class|actual fun|actual class' src/ --include='*.kt' \| wc -l` | **0** |
| 平台分支代码 | `grep -rnE 'os\.name\|System\.getProperty\("os' src/ --include='*.kt'` | **无命中**（桌面只有数据目录回退，见 §4） |

> 结论：**「移除/隔离 iOS/Web」在本仓库是空操作**。不能因为任务书假设它们存在就去做无对象的删除，也不能声称「已移除」。若你所指是 `readest-src/`、`Readest/`（第三方参考项目、已 gitignore，`AGENTS.md` 明令不得改动），或另一个仓库，请明确（问题 Q5）。

## 3. 三平台现状与缺口

| 平台 | 当前可构建？ | 证据 | 缺口 |

## 4. 平台相关代码清单（按耦合类型）

来源：`全平台与同步/阶段0-补充核对-数据落盘与依赖图.md`（已逐行核实）+ 本次新增核查。

| 耦合类型 | 代表性文件 / 事实 | 是否阻塞三平台 |
| --- | --- | --- |
| **Android 专有**（`:app`，88 个 `.kt`，其中 65 个 import `android/androidx`） | `MainActivity`、全部 Compose 屏、`TtsPlaybackService`、`ReviewReminder`、`PdfImporter`（pdfbox-android）、SAF 导入、`AndroidManifest.xml` | **是**，若三平台=不含 Android，则这一整块要移除/隔离 |
| **平台面接口**（已抽象） | `shared/app/AppContext.kt`：`filesDir` + `prefs(name)`；Android 实现 `AndroidAppContext`，桌面实现 `DesktopAppContext` | 否（已具备两端实现） |
| **桌面平台分支** | `LinguaReaderApp.resolveHomeDir()`：`-Dlr.home` → `%APPDATA%/LinguaReader` → `~/.linguareader/home`（仅数据目录回退，无 OS 判定分支） | 否 |
| **桌面专有依赖** | `jcefmaven`（CEF 内核，按 OS 下载）、`sqlite-jdbc`、`mp3spi` | 否（`currentOs` 自动选） |
| **共享内核**（`:shared`，52 个 `.kt`） | 零 `android.*`/`androidx.*`（CI grep 执法） | 否 |
