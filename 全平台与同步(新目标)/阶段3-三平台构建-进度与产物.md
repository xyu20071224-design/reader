# 阶段 3 三平台构建：进度与产物

> 采集 2026-09-20。**只记录实测；本机没有的能力标注未验证，不伪造。**

## 1. 本轮做了什么

1. 桌面打包格式由「只配 Linux 的 AppImage」改为**按宿主 OS 选择**（`src/desktopApp/build.gradle.kts`）：
   - Windows → `TargetFormat.Exe`
   - macOS → `TargetFormat.Dmg`
   - Linux → `TargetFormat.Deb`
2. 新增 CI 三平台矩阵 [.github/workflows/platform-build.yml](.github/workflows/platform-build.yml)：`ubuntu-latest` / `windows-latest` / `macos-latest`，各自跑 `:shared:test`+`:desktopApp:test`、`createDistributable`、`packageDistributionForCurrentOS`，并上传产物。

## 2. 格式选择的实测依据

| 观察 | 命令 | 原始结果 |
| --- | --- | --- |
| AppImage **不产出单文件** | `./toolchain/build.sh :desktopApp:packageAppImage` | `BUILD SUCCESSFUL`，但 `find … -name '*.AppImage'` 为空；`compose/logs/packageAppImage/*-err.txt` = `Input length = 1` |
| Deb 在本机不受支持 | `./toolchain/build.sh :desktopApp:packageDeb` | jpackage 退出码 1，err = `错误：类型 [deb] 无效或不受支持`；`which dpkg dpkg-deb` → 都不存在（CI 的 ubuntu-latest 自带） |
| app-image 三平台通用 | `./toolchain/build.sh :desktopApp:createDistributable` | `BUILD SUCCESSFUL`；产出 `src/desktopApp/build/compose/binaries/main/app/LinguaReader/bin/LinguaReader`，`file` 判定为 **ELF 64-bit LSB pie executable, x86-64** |
| jpackage 只能为宿主 OS 打包 | 官方行为 + `packageName/packageVersion` 配置 | 因此 Windows/macOS 产物必须由对应 OS 或对应 CI runner 构建 |

## 5. 未验证（明确列出）

| 项 | 原因 | 复现方式 |
| --- | --- | --- |
| Windows Exe 产物 | 本机是 Linux，无 Windows | push 后看 `Platform Build / 桌面构建 (windows-latest)` |
| macOS Dmg 产物 | 本机无 macOS | push 后看 `macos-latest` job |
| Linux Deb 产物 | 本机缺 `dpkg-deb` | CI 的 ubuntu-latest；或本机装 dpkg 后 `packageDeb` |
| app-image **GUI 启动** | 需要图形会话，本轮未启动窗口 | 在桌面环境执行 `bin/LinguaReader` |
| CI 是否真的绿 | **尚未 push**，Actions 未跑 | push 后以 Actions 页为准 |

> 结论：**「三平台可构建」目前只有 Linux 有本机证据**；Windows/macOS 依赖 CI 首跑。在 CI 跑绿之前，不声称三平台可构建。

### 首跑过程中修掉的真问题（都有 CI 证据）

| # | 现象 | 根因 | 修复（提交） |
| --- | --- | --- | --- |
| 1 | Windows 上 `AudioPackGeneratorContractTest` 2 条失败 | ① 临时目录名用了字面量 `<book>`（`<` `>` 是 Windows 非法文件名字符）；② 生成器最后的中文 `print` 在 cp1252 控制台抛 `UnicodeEncodeError` 而非 0 退出 | `c0a9f2f`（目录名）、`f85d229`（生成器强制 UTF-8 输出） |
| 2 | macOS 上 8 条 `PythonServerE2ETest` 全报「服务端 20 秒内未就绪」，`server.log` 为空 | `ThreadingHTTPServer.server_bind` 调 `socket.getfqdn()` 做反向解析，macOS 上阻塞到健康检查窗口之外 | `ad57090`（自定义 `SyncHttpServer` 跳过 getfqdn） |
| 3 | Windows 上 `generator key derivation` 仍失败（`NameError/SyntaxError`） | Windows 命令行解析破坏 `python -c` 里的引号与换行 | `05d4a3f`（改为写临时 .py 文件再执行） |
| 4 | 某次 windows job 依赖解析失败（非测试） | 阿里云镜像 `maven.aliyun.com` 返回 502 | `7fd1bae`（Gradle 步骤有限重试；不改仓库镜像顺序） |
| 5 | 无法读取 job 日志（需 token） | GitHub 限制 | `c0a9f2f`（失败用例写成 `::error` 注解，可匿名经 check-runs API 读取） |

> 因此「三平台可构建」现在有 **CI 产物级证据**，不再是推测。
> 仍**未做**：三平台各自的**运行**验证（GUI 启动/冒烟）—— 产物已产出，但本机只有 Linux，Windows/macOS 的启动验证仍需实机或 CI 冒烟步骤。
