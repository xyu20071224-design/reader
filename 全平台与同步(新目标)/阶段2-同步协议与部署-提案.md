# 阶段 2 提案：自托管云同步协议 / 数据模型 / 鉴权 / 部署（v1，待你确认）

> 用户已定输入（2026-09-19）：
> 1. 平台 = **Android 保留 + Windows / Linux / macOS 三端补齐**；
> 2. 后端 = **自建同步服务端，部署在腾讯云 / 阿里云的云服务器（CVM / ECS）**；
> 3. 传输与鉴权 = **REST + JSON、账号密码换令牌**；
> 4. 同步范围 = **阅读进度 / 生词 / 术语表备注 / 偏好**；**不上传本地书籍正文**。
>
> **本文件是提案，不是已确认设计。你确认前我不写服务端代码。**

---

## 1. 边界与不做

- 同步：阅读进度、生词（含复习状态）、术语表用户可编辑字段、用户偏好。
- **不同步**：书籍正文与解压产物、TTS 缓存、任何 API Key / token、与设备绑定的设置（服务器地址、系统音色 id）。
- 只做自托管服务端；不引入第三方 BaaS，不引入厂商 SDK。
- 客户端不新增 HTTP / JSON 依赖：沿用现有的 java.net.HttpURLConnection + org.json（与 GitHubUpdateChecker 同款）。

## 2. 架构

    [Android :app]  ─┐
                     ├─ HTTPS/JSON ─→ [同步服务端 (Python stdlib)] ─→ SQLite(WAL)
    [桌面 :desktopApp]┘                        ↑
                                        nginx 终止 TLS
                                        (腾讯云 CVM / 阿里云 ECS)

- 客户端共用同一份 :shared/sync 纯逻辑（Android / Win / Linux / macOS 四端同语义）。
- 服务端**不做业务合并**：只做「按 updatedAt 的整条记录 LWW」与变更流；字段级合并全在客户端（复用已提交的 ConflictResolver）。
- 不传输书籍正文，服务端无法还原书，只拥有阅读产生的用户数据。

## 3. 同步范围（collection 定义）

| collection | 记录 id（键） | 同步的 payload | 明确不同步 |
| --- | --- | --- | --- |
| progress | bookId | title / author / sourceFormat + chapterIndex / pageIndex / progress / locusBlockIndex / locusCharOffset / locusAnchor / ttsChapterIndex / ttsSentenceIndex / progressUpdatedAt | extractedDir、coverRelativePath、chapters（都是设备本地导入产物） |
| vocabulary | SavedWord.id（小写词头） | SavedWord 全字段（含复习状态与 surfaceForms） | — |
| glossary | bookId + "::" + term | term / kind / note（用户可编辑字段） | AI 派生释义等非用户字段 |
| preference | 逻辑键，如 reader_preferences.fontPercent | 字符串值 | 凭据类键（ai_settings.api_key、cloud_tts_settings.server_token、mimo_api_key…）、设备绑定键（server_url、system_*_voice、mimo_model） |

## 4. 记录模型

客户端提交与服务端返回的记录（JSON）：

    {
      "collection": "vocabulary",
      "id": "study",
      "updatedAt": 1758300000000,
      "deletedAt": 0,
      "payload": { "headword": "study", "meaning": "n. 学习", "...": "..." }
    }

- updatedAt：客户端墙上时钟毫秒（本树已在 Book.progressUpdatedAt / SavedWord.updatedAt 落地）。
- deletedAt：0 = 未删除；> 0 = 墓碑（删除时间）。
- 服务端额外维护 serverSeq（每用户单调递增）与 serverUpdatedAt，仅用于变更流游标，不改写客户端 updatedAt。

## 5. API（v1）

| 方法 | 路径 | 鉴权 | 请求 | 响应 |
| --- | --- | --- | --- | --- |
| GET | /api/v1/health | 无 | — | { "status": "ok", "version": 1 } |
| POST | /api/v1/auth/register | 无（可被部署开关关闭） | { username, password } | 201 { "userId": "..." } |
| POST | /api/v1/auth/login | 无 | { username, password } | { "token": "...", "expiresAt": 1758900000000 } |
| POST | /api/v1/auth/logout | Bearer | — | 204 |
| GET | /api/v1/changes?since=SEQ&limit=500 | Bearer | — | { "records": [...], "nextSeq": N, "hasMore": bool } |
| POST | /api/v1/changes | Bearer | { "baseSeq": N, "records": [...] } | { "applied": [...], "conflicts": [...], "nextSeq": N } |
| GET | /api/v1/state | Bearer | — | { "records": [...], "nextSeq": N }（新设备首次全量引导） |

错误：统一 { "error": { "code": "...", "message": "..." } }；HTTP 400/401/403/409/429/500。

POST /api/v1/changes 的服务端规则（逐条）：
1. 无既有记录 → 写入，分配 serverSeq；
2. 传入 updatedAt 严格大于既有 → 覆盖写入，分配 serverSeq；
3. 否则 → **不改服务端**，把既有记录放进 conflicts 返回。

## 6. 鉴权与安全

- 口令：PBKDF2-HMAC-SHA256，16 字节随机盐，迭代 ≥ 210000，仅存盐与派生值。
- 令牌：32 字节随机（secrets.token_urlsafe），服务端只存 SHA-256 哈希 + 过期时间（默认 30 天）；登出即吊销。
- 传输：**必须 HTTPS**；证书由 nginx 终止。
- 客户端令牌存储：**进系统安全存储，不落明文**（Android 复用现有 Keystore 能力；桌面实现见 §12 的子决策 D4）。
- 服务端不记录请求体日志；数据库文件权限 0600；建议仅对可信 IP 开放 22。

## 7. 离线与冲突流程

客户端状态：outbox（待推送变更）、cursor（已拉取到的 serverSeq）。

    本地编辑 → 写本地 + 追加 outbox(updatedAt=now)
    联网时：
      ① pull: GET /changes?since=cursor → 逐条并入本地（merge 规则见下）
      ② push: POST /changes {baseSeq, outbox 记录}
      ③ 若返回 conflicts：对每条用 ConflictResolver.merge(本地, 远端)
         → updatedAt = max(local, remote) + 1 → 重新入 outbox → 回到 ②（上限 5 轮）
      ④ 清空已确认的 outbox；cursor = nextSeq

- 合并规则（沿用已提交的 ConflictResolver，可按你的意见调整）：
  * progress：整组位置向量 LWW，保留本机 extractedDir/chapters；
  * vocabulary：文本字段 LWW + 复习状态单调取大 + addedAt 取早 + surfaceForms 并集；
  * glossary / preference：LWW；preference 额外做「提交前版本检查」。
- 离线：outbox 持久化于 filesDir/sync/outbox.json；重试指数退避（1s/2s/4s…上限 60s）；进程重启后续传。
- 删除：写墓碑（deletedAt）；服务端保留 N 天后 GC（N 可配，默认 30 天）。

## 8. 服务端实现选型（建议）

- **Python 3 标准库**（http.server.ThreadingHTTPServer + sqlite3 + hashlib + hmac + secrets + json），**零 pip 依赖**——仓库已有 Python 工具链，云主机上无须装任何包。
- 存储：单文件 SQLite（WAL 模式）。
- 表：

      users(id TEXT PK, username TEXT UNIQUE, pw_salt BLOB, pw_hash BLOB, seq_counter INTEGER, created_at INTEGER)
      tokens(token_hash TEXT PK, user_id TEXT, expires_at INTEGER, created_at INTEGER)
      records(user_id TEXT, collection TEXT, id TEXT, updated_at INTEGER, deleted_at INTEGER,
              payload TEXT, server_seq INTEGER, PRIMARY KEY(user_id, collection, id))
      tombstones(user_id, collection, id, deleted_at, server_seq)   -- 变更流保留期

- 单文件部署：sync-server/server.py + sync-server/schema.sql + sync-server/README.md。

## 11. 验证与验收（对应你的验收标准）

| 场景 | 做法 | 可观测证据 |
| --- | --- | --- |
| 增量同步 | 客户端 A 改进度 → B 拉到 | 两端 metadata.json 字段一致 + 服务端日志 |
| 离线写入后合并 | 断网改 A、联网改 B → 恢复 → 两端收敛 | outbox 清空、两端最终一致 |
| 冲突：同一本书进度 | A/B 同时改同一 bookId 的不同页 | 按 updatedAt 胜出，两端一致（固定时间戳夹具可复现） |
| 冲突：同一条生词并发编辑 | A 改释义、B 复习同一词 | 文本取较晚、复习状态取大，两端一致 |
| 冲突：同一条术语备注 | A/B 同时改同 term 的 note | LWW 收敛，两端一致 |
| 跨平台 | 两个客户端来自两个平台 | 见 D5 路径选择 |

单测在 :shared（纯逻辑，假 SyncApi），端到端用本机起服务端 + 两实例。
