## 2. 阶段 1（平台裁剪）草案 —— **取决于 Q1**

### 2.0 先说结论

任务书预设「iOS/Web 构建目标存在，需要移除」。**实测不存在**（清单① §2 给了负证据：无子项目、无 KMP/js/wasm、无 Xcode/Swift、无 iOS/Web Gradle 任务、CI 无对应 job、条件编译 0 处）。因此阶段 1 **没有可移除的 iOS/Web 对象**，我不会伪造这项工作量。

当前唯一与「三平台」冲突的是 **Android（`:app`）**，两条路线：

### 路线 A：三平台 = 桌面三端，Android 退出一线（你若是此意）

| 步 | 动作 | 验证 | 回退 |
| --- | --- | --- | --- |
| 1 | 记录基线：`:shared:test` / `:desktopApp:test` / `:app:testDebugUnitTest` 全绿 | 测试 XML 计数 | — |
| 2 | 把 `:app` 从 `src/settings.gradle.kts` 的 `include` 移除（**不删代码**），并同步 CI | `:shared:test`+`:desktopApp:test` 仍绿 | 恢复 include 即回退 |
| 3 | 若确认不再需要，`git mv src/app archive/android-app/` 并在 `settings.gradle.kts` 注释写明归档原因与恢复方式 | 同上 | `git mv` 回退 |
| 4 | iOS/Web 裁剪 | 记录负证据（无对象） | — |
| 5 | 修复三平台打包格式（Msi/Exe、AppImage/Deb、Dmg）+ macOS 构建脚本 | 各平台产物路径或 CI 记录 | 保留旧配置 |

- **不触发**预案里的「共享核心被 iOS/Web 依赖」情形：`:shared` 是独立模块，且**无任何模块反向依赖 `:app`**（实测 `grep project(":app")` 无命中）；`:desktopApp` 也**不使用** `SharedString`（实测无引用），所以去掉 `:app` 后桌面仍可独立编译。
- 代价要说清：Android 端是当前**唯一功能完整的 UI**（88 文件）；`:desktopApp` 只有 13 文件、5 个面板。若走路线 A，「产品」实际会缩水到桌面壳的现有能力，补齐 UI 属于新增开发，**不在本次「不扩大范围」的许可内**——除非你把它算进云同步交付。

### 路线 B：保留 Android，只补齐桌面三端（另一种理解）

那么阶段 1 的「裁剪 iOS/Web」仍是空操作；实际工作变成「加 Windows/macOS 打包与 CI」。「不引入第四种平台」仍成立（Android 是存量，不是新引入）。这条路线与「收敛为三平台」字面冲突，但工程量与风险最低。

> 两条路线的**触发问题 = Q1**。

## 3. 阶段 2（云同步）草案 —— **取决于 Q2**

按你的预案：「仓库中找不到云同步的后端地址、数据 schema、鉴权配置 → 先确认后端选型与协议，不要自行假设或搭建」。现状确认：**全都没有**。

需要你给的最小输入集：

| 输入 | 为什么必须 |
| --- | --- |
| 后端形态 | 自建服务端 / WebDAV / 现有第三方服务（你指定）三选一；决定协议与依赖 |
| 协议 | REST+JSON / WebDAV / 你指定的既有 API 规格 |
| 鉴权 | 账号密码 / Token / OAuth / 设备码；决定凭据存储与刷新 |
| 托管 | 你自己部署 / 云厂商 / 局域网；决定可复现验证怎么做 |
| 同步数据范围 | 进度、生词、术语表备注、译本档案……哪些同步、哪些只留本地（书籍正文一律不传） |
| 冲突策略 | 直接给你定义的规则；或复用本树已有的 `ConflictResolver`（见 Q4） |

**在你回答前我不会写任何同步后端/协议代码。**

## 4. 阶段 3/4 草案（不依赖 Q1/Q2 的部分）

- **阶段 3（三平台回归）**：CI 加 `windows-latest` / `ubuntu-latest` / `macos-latest` 三个 job，各自构建 `:desktopApp` 分发物并跑冒烟（`:desktopApp:test` + 启动脚本）；本机只能验 Linux，Windows/macOS 以 CI 记录为准（预案：无法本机验证就用 CI 并说明）。
- **阶段 4（证据）**：每阶段交付固定格式 —— 「改动文件 → 执行命令 → 原始输出（截断保留关键段）→ `git diff --stat`」。云同步端到端证据要求：**≥2 个客户端、跨 ≥2 个平台**（例如 Linux 桌面 + Windows 桌面，或 Linux + Android 若保留），覆盖离线写入与冲突。
