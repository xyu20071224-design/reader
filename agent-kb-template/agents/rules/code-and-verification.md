# 规则：代码与验证纪律

> 依据：【列出本规则的核对来源：构建配置、目录结构、git 历史，附日期 @ commit】。

## 实现范围

写**解决当前问题的最小代码**。

- 不加没被要求的功能。
- 单处使用的代码不要抽象。
- 不为「以后可能需要」加配置项。
- 不为不可能发生的分支写错误处理。
- 收尾自问：资深工程师会觉得这段过度设计吗？会，就简化。

## 默认值与标识符：单点定义

外部服务的模型名、端点、默认参数这类**散落在多处、必须保持一致**的值，只允许一个权威出处。

- 别在多个地方各写一份默认值（典型三重：数据类默认值 + 存储层 load 回退 + save 回退）。改一处漏一处，只在真实业务调用时才暴露。
- 改名/改默认值要**全局搜索**，含测试快照与预设表；搜完再改。
- **「连通性测试通过」≠「标识符有效」**：探测请求往往只发最小负载，可能不触发对模型名/端点参数的校验。要确认标识符被服务端接受，用「列举可用项」或一次真实业务请求。

## 平台约束

- 【运行时/SDK 下限】。用高版本能力必须做版本判断或选兼容实现。
- 【已声明的组件/权限/服务清单】。新增组件要同步注册，否则运行时才炸。
- 【备份策略 / 数据安全假设（如 allowBackup=false 时不能依赖系统备份）】

## 测试与验证

| 改动类型 | 最低验证要求 |
| --- | --- |
| 纯逻辑（算法/状态机/解析） | 【单测命令】，并补/改对应单测 |
| UI 结构 | 【含资源加载的单测，或仪器测试】 |
| 渲染 / 手势 / 【平台特有交互】 | **真机或模拟器实测**，单测测不出来 |
| 后台服务 / 通知 / 系统集成 | **真机实测**，必要时抓日志 |
| 联网功能 | 未配置、失败、超时三条路径都要走一遍，确认降级生效 |

- 【真机验证的设备、并存包/数据保护做法（别覆盖真实用户数据）】
- 验证结论写进【VALIDATION.md】，截图/证据放【目录】；大产物放【gitignore 目录】。

## 跑构建 / 测试：判据是产物，不是作业状态

- **别用「捕获输出再回传」的包装脚本跑长任务**（把 stdout 重定向进管道/文件、由外层转交）：构建守护进程会继承并长期持有重定向句柄，客户端已退出而管道 EOF 不来，外层 shell 假挂——作业状态显示 running，构建其实早已结束（成功或失败）。
- **判据是产物**：测试结果文件（`**/test-results/**/*.xml` 的 `tests/failures/errors`）、构建产物（体积/时间戳），不是作业 / 流水线状态。
- 长任务周期看日志 mtime；一小时不动的日志就是答案。
- 多模块仓库的测试任务名各不相同（如 `:app:testDebugUnitTest` vs `:shared:test`）；跑「全量」前先确认任务名覆盖到改动的模块——只跑一个模块的任务不会触发另一个模块的测试。

## 联网与隐私（有产品承诺才适用）

新增任何出网调用必须同时满足：

1. 默认关闭；
2. 有用户可见的显式开关；
3. 未配置 / 失败 / 超时都有**降级路径**，且降级后功能仍可用；
4. 出网的数据范围写清楚，不夹带用户不知道的内容。

## 提交

- 提交前：测试跑过、不带上大文件（构建产物/模型/日志）、不带上密钥与本地配置文件。
