## 项目约定

- **提交信息**：【前缀集，如 feat/fix/refactor/test/chore】+【语言】描述，一次提交只做一件事。
- 【文案/i18n：资源文件位置、多语 key 成对维护、命名风格】

- **纯逻辑要能单测**：状态机/算法抽成不依赖平台框架的类，新增算法先写单测。

## Git 工作流

- 远端【origin = …】；【main】是唯一权威分支。
- **合并即推送**：feature 合回权威分支后立刻 push（本地领先即无备份）。
- feature 分支也要推（`git push -u origin feat/<主题>`）；合并后即删。
- 动手前先 `git fetch`；**push 被拒 = 远端分叉，停下来查清再动**。
- **绝不 force-push 权威分支**；确需覆盖先备份远端现状成分支。
- 【CI：哪些分支/PR 自动跑什么，红了先修再合并】
- 【并行会话纪律：同一时间尽量一个会话操作本仓库；确需并行，开工前 fetch 且分工不重叠文件】
- 【发布：tag 规则、Release 资产去留】

## 验证纪律

| 改动类型 | 最低验证要求 |
| --- | --- |
| 纯逻辑（算法/状态机/解析） | 【单测命令】必跑，并补/改对应单测 |
| 【UI 结构】 | 【…】 |
| 【渲染/手势/平台特有交互】 | **真机或模拟器实测**，单测覆盖不到 |
| 【后台服务/通知/系统集成】 | **真机实测**，必要时抓日志 |
| 【联网功能】 | 未配置/失败/超时三条路径都走一遍，确认降级生效 |

- 【历史验证设备及其已知怪癖（哪些跳过属预期，不算回归）】
- 【禁区：碰过会翻车的地方，一句话事故 + 详见哪份记忆文件】
- 验证结论写进【VALIDATION.md】，证据放【目录】。
