## 证据与修改范围

基线 `MainActivity.rememberEnglishSpeaker` 只使用 `SpeechReadiness` 等待初始化，随后直接 `setLanguage` / `speak`；未消费两者返回值、未在该路径设置进度回调，使用固定 utterance ID。源码证据能确认这些可靠性缺口，不能证明它们就是用户听到的首音缺失根因。本轮未用模拟结果冒充真实录音，也未声称跑过基线的音频失败测试。

- `SingleWordSpeaker` 保持初始化前只补最后一次请求，按引擎代次和唯一 utterance ID 隔离过期回调。初始化或英语语音不可用时不提交播放；请求拒绝、真实播放错误或非预期停止有类型化失败回调。未发生用户请求时初始化失败保持安静，下一次明确点击可以重试。
- `AndroidSingleWordSpeechEngine` 只封装现有一次性系统 TextToSpeech，保留 `QUEUE_FLUSH`，通过主线程 Handler 串行初始化/进度回调与 UI 操作。销毁后不补播，不加静音、固定等待、网络服务或音频预热。
- 诊断最多记录 1024 条调试事件，字段只有阶段、代次、请求 ID 和状态码，不包含单词、词组或阅读正文。
- 新增 `SingleWordSpeakerTest`；既有 `SpeechReadiness` 与其测试未改。

`MainActivity.kt` 未直接修改。`MainActivity.patch` 是交给集成人的最小装配补丁；调用点还需提供 `onFailure: (SingleWordSpeaker.Failure) -> Unit`，在 ModalBottomSheet/Dialog 之上显示可见反馈。未经这一步接线，新控制器还未进入产品调用链。

## 集成人接线

失败类型为 `ENGINE_UNAVAILABLE`、`LANGUAGE_UNAVAILABLE`、`REQUEST_REJECTED`、`PLAYBACK_FAILED`。后两类可共用 `tts_word_playback_failed`，前两类分别使用 `tts_word_unavailable`、`tts_word_language_missing`；双语资源和 UI 由集成人统一接入，本分支不改 strings。

回调必须在主线程调用，适配器已保证；控制器在独立 JVM 测试中由可控假引擎驱动。`start()` 可预初始化；`speak()` 在尚未初始化时也能安全保存请求；`close()` 终结当前控制器。Compose 装配使用 `rememberUpdatedState` 保持当前错误处理函数。
