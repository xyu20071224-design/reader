# 句内节奏播放与缓存接口方案

本方案经集成人确认后已按运行时路线实施；以同目录 `报告.md` 和代码为最终交付。持久化 pipeline=3、音频包及句/声部编号保持，新增可选 planned 能力、短语缓存和模式设置入口。真实设备/云试听仍待验收。

## 建议保持的契约

1. `TtsChapter` 的句/声部片段编号、`TtsUtterance.segmentIndex` 和 `TtsPipelineContract.VERSION=3` 保持现状。句内节奏部分使用独立运行时 `partIndex`，不能拿它覆盖持久声部片段编号。
2. 新 `ProsodyPlanner` 默认 `ORIGINAL`，该模式原样返回源朗读片段。`PHRASES` 是待试听的候选策略：只在够长的自然分句边界切分，保护数字/缩写/引号/括号，可接收调用方掌握的跨块引语保护范围；所有部分保留父句/声部/角色并给出原文偏移。
3. 每个运行时部分的末尾停顿只作用于下一个内部部分，最后一部分始终为零；原有引擎句末停顿只发生一次。具体停顿和倍率是候选产品值，尚未试听，不将其宣称为语言标准。
4. 进度继续保存父句，角色映射按父声部来源，高亮可细化到部分的原文范围。源偏移未知时不猜造新位置。

## 实际播放的最小新增接口

建议先引入独立可选能力接口，例如 `PlannedTtsSynthesizer.speakPlan(parentUtteranceId, plan, voice)`，而非直接破坏所有现有 `TtsSynthesizer` 实现。

后端内部负责子请求 ID、逐部分合成/播放和内部停顿；对原引擎仍只报告父请求的一次 start 和一次 done/error。stop/新请求/换模式必须用父请求代次取消后端的全部旧任务，不能仅靠可被新请求复位的 `stopped` 布尔值。当前五段式 utteranceId 及 CloudTtsSynthesizer 的定位解析不应被随意追加字段破坏。

**禁止把新部分的 text 配上旧父 utteranceId 直接送入现有 CloudTtsSynthesizer.speak。** 现有缓存按父句/声部定位，这样会把不同部分读写到相同的完整音频文件，命中错误内容。

系统 TTS 可按计划逐部分设置 rate。当前云后端公共契约只有文本/音色到文件的合成，尚无可依赖的通用词时间戳或 SSML/原生节奏保证；新增原生能力必须经过具体后端核对。不能猜测音频时间戳切旧 MP3。

## 云端缓存与预生成

建议为短语合成使用独立运行时缓存命名空间，身份至少包含：

- 原书/章/父句/父声部；
- 合成引擎与真实有效音色；
- 源片段文本指纹；
- 规划策略版本及会影响分割/合成的配置指纹；
- 运行时部分编号与实际部分文本指纹。

已存在的完整音频缓存及 `TtsCacheKey` 不迁移、不覆盖，仍服务原始节奏。纯本地全局播放变速不进入合成指纹，不应重新计费。只有后端原生合成需要的节奏参数才纳入合成身份；本地播放倍率本身不应无故使音频作废。

预生成与现场播放必须消费同一个规划器、同一份策略和同一音色解析。不能只改播放端而让 `prepareChapter/prepareBook` 继续按另一份拆分生成。后续实现时应由一个所有者统一改 Android 云端预生成、实际播放和必要桌面能力回退。

## 音频包与版本边界

在保留现有持久句/声部映射的建议路线下，旧包可继续在原始节奏模式播放；它没有部分级定位，不能假装支持新的句内控制。用户可选择保持包的原节奏，或在已授权的引擎与联网条件下显式生成新的节奏版本。不得静默绕开包并重复云合成。

若后续决定改变持久句/声部映射，则必须改走另一条完整升级路线：升级 pipeline、缓存键、manifest 校验和打包工具；不兼容旧包可以保留文件，但拒绝用于新管线播放并给出明确提示。不得将“保留旧包”解释为绕过 pipeline 兼容检查。

两条路线不能混合实现。未经集成人确认，本提交不升 pipeline 或包格式。

## 集成与验收边界

可选接口、父/子回调、短语缓存、预生成与旧包默认回退已接入；集成人接 UI 与可见回退提示。仍需对设备音频、真实云端、多角色、断网、调速与导航中断逐项取证，不能将自动回归通过当作 Q2-c04b 听感完成。后端真实配置仅进入新短语身份，凭证不入身份；旧原节奏键格式不变；默认 MiMo 身份兼容，仅非默认实际模型追加摘要隔离旧默认音频。
