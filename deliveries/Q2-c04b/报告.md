## 停顿竞态的失败证据

生产引擎在 `handleUtteranceDone` 进入时校验 utterance ID，但 `delay(250)` 后直接推进当前全局句位置。新增 7 个直接调用真实 `TtsPlaybackEngine` 的虚拟时钟测试，在引擎未修改时得到 **7 tests / 7 failures / 0 errors / 0 skipped**：

| 停顿期间的操作 | 应保留的播放序列 | 基线实际序列 |
| --- | --- | --- |
| 下一句 | A → B | A → B → C |
| 上一句 | B → A | B → A → B |
| 暂停后恢复 | A → A | A → B |
| 调速重播当前句 | A → A | A → A → B |
| 换书到新书第一句 | 旧 A → 新 A | 旧 A → 新 A → 新 B |
| stop 后重启 | A → A | A → A → B |
| 同一请求重复 onDone | A → B | A → C → C |

这不是假后端替代音频听感，而是用生产状态机验证导航顺序；fake synthesizer 只记录真实引擎提交的文本与请求。暂停恢复的期望与已有 `pauseStopsThenResumeRespeaksCurrent` 契约一致。

## 最小修复与规划器

- `TtsPlaybackEngine` 仅增加 4 行：保存当前导航代次；句末等待结束后再次核对代次、playing 和完整 utteranceId/attempt。旧等待不再推动已被用户操作或另一完成事件替换的位置。
- 新增纯 `ProsodyPlanner`，默认 `ORIGINAL` 原样保留源片段。候选 `PHRASES` 按足够长的自然标点边界生成运行时单元，保留父句/声部/角色与原文偏移；保护数字、时间、URL、缩写、引号和括号，可接收跨块引语保护范围。
- 运行时 `partIndex` 与持久 `segmentIndex` 分开；最后一部分的 pause 为零，避免将原有句末停顿叠加两遍。停顿和尾段倍率为待试听的候选值，尚不是已批准最终产品参数。
- 不修改 `SentenceSplitter`、`QuoteSpans`、`TtsChapter`、缓存键、pipeline 版本、音频包或 UI，规划器尚未进入生产播放路径。

后续真实播放与缓存边界见同目录 `播放与缓存接口方案.md`。尤其不能把新部分文本连同旧父 utteranceId 送入现有云合成器，否则会复用父片段文件造成内容错位。
