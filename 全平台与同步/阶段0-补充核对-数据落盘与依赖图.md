### 书库仓库 `LibraryRepository`（`:shared`）
- 根：`booksDir = <filesDir>/books`；每书 `books/<id>/metadata.json`；旧 `library.json` 存在时迁移。
  证据：`src/shared/src/main/java/com/linguareader/shared/data/LibraryRepository.kt:17-21,28-40`。
- **读取会过滤**：`extractedDir` 目录必须存在且 `chapters` 非空，否则该书从书架静默消失（元数据文件仍在）。证据：同文件 `37`。
- **写进度 = 读盘合并，不是整份覆盖**：先 `readMetadata(book.id)` 取盘上最新，再 `copy(...)` 只改本次字段。证据：同文件 `71-97`（注释 `48-56` 明确说明为何不能信任调用方快照）。
- **写盘纪律**：`temp.writeText` → `renameTo`；rename 失败时**先删目标再 rename**，再不行就让 `.tmp` 原地留着；**刻意不抛异常**（800ms 回写路径）。证据：同文件 `150-163`。
- **v1→v2 迁移是逐条的**：一条坏记录不再拖垮整批；迁出过东西才删 `library.json`，一条都没迁成功则保留旧文件。证据：同文件 `172-188`。
- 删书：删除 `books/<id>` 目录（含 metadata.json），带 canonicalPath 前缀校验。证据：同文件 `139-148`。

### 生词仓库 `VocabularyRepository`（`:shared`）
- 文件：`<filesDir>/vocabulary.json`。证据：`src/shared/src/main/java/com/linguareader/shared/data/VocabularyRepository.kt:13-14`。

## 2. 这些事实对同步设计的直接影响（阶段 2/4 必读）

1. **同步并入必须走 read-modify-write**：`LibraryRepository.saveProgress` 与 `VocabularyRepository.save` 都依赖「盘上最新值 + 只改本次字段」。同步拉取落地时若整份覆盖，会重现注释里描述过的「边听边读互相打回旧值」事故。
2. **`SavedWord.id` 天然是跨书全局主键**（小写词头）——同步的冲突键不用另造；但这也意味着**同一个词在两本书上只存一条**，同步合并时按 id 收敛即可。
3. **`Book` 目前没有任何 `updatedAt`/`rev`**（阶段 0 已确认）——冲突裁决所需版本字段必须新增，且用 `opt*` 默认值保持老数据可读。
4. **书库的「元数据在、`extractedDir` 丢」= 书从书架消失**：同步**只同步 metadata，不同步书籍正文**，因此在新设备上必须明确「书架上没有实体书」的呈现与再导入路径，不能让读到的 metadata 变成幽灵条目。
5. **写盘是「宁可这次没存上，也不写坏」**：同步落地必须沿用同一纪律（tmp+rename、不抛异常），否则会把现有可靠性拉低。
