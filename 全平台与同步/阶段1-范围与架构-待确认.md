## 2. 同步方案对比与默认选型

### 2.1 对比

| 维度 | A 自建最小服务端（参考实现） | B 第三方 BaaS（Firebase/Supabase 等） | C 文件式同步（WebDAV / 用户自备网盘） |
| --- | --- | --- | --- |
| 成本 | 一次性写服务端 + 用户自付主机 | 免运维起步，超量计费 | 零服务端代码；依赖用户已有 WebDAV |
| 离线能力 | 完全可控（本地队列 + 增量） | SDK 自带离线，但服务端不可控 | 完全本地可控，冲突靠文件时间戳 |
| 冲突处理 | 完全可控（本文第 3 节策略） | 受 SDK 语义限制（有限可控） | 弱：只能靠 ETag/时间戳 LWW |
| 隐私 | 数据只到用户自己的机器/自己部署的服务器 | **用户数据出境到第三方** | 数据到用户自己的网盘 |
| 维护量 | 中（服务端 + 版本兼容） | 低（但被厂商生命周期绑定） | 低（协议简单） |
| 依赖重量 | 无新客户端依赖（现有 `HttpURLConnection` 先例） | **引入重量级 SDK**（违反硬约束） | 无新依赖（HTTP 即可） |
| 厂商锁定 | 无 | **强绑定** | 无（协议标准） |

### 2.2 默认选型

**D-02（默认）**：采用**「接口 + 可替换适配器」**结构：
- 默认实现 = **A 自建最小服务端**（可本地一键起，含测试），部署说明随阶段 4 交付；
- 同时实现 **C WebDAV 适配器**作为第二个可替换后端（证明「不绑一家厂商」）；
- **B 第三方 BaaS 本期不做**（数据出境 + 重量级依赖 + 厂商锁定，违反硬约束；要用需你明确批准）。

## 3. 冲突解决策略

按数据类型分别定，**不引入 CRDT 库**（重量级依赖；当前无「多人实时协作编辑长文本」场景）。

| 数据 | 现状（阶段 0） | 策略 | 理由 |
| --- | --- | --- | --- |
| **阅读进度** | `Book` 内 `chapterIndex/pageIndex/progress/locusBlockIndex/locusCharOffset/locusAnchor/ttsChapterIndex/ttsSentenceIndex`，落 `books/<id>/metadata.json` | **last-write-wins，但按「位置向量」整组原子更新**（新增 `progressUpdatedAt`）；不做字段级混搭 | 进度表达「用户当前读到哪」，语义是覆盖而非累积；若字段级混搭会出现「新章号 + 旧锚点」的位置错乱 |
| **书签** | **功能不存在**（阶段 0 §4.3） | 本期不新增；若阶段 2 后要加：`add` 用稳定 id 幂等合并，`delete` 用 **tombstone**（`deletedAt`），集合做 **union + tombstone 优先** | 集合语义天然可合并；无需 CRDT |
| **笔记** | **无独立笔记功能**。现有「笔记类」= 生词卡 `SavedWord`、术语表 `note`、AI 译本 `style.json.notes` | 生词卡：按 `id`（小写词头）键做**字段级合并**——复习计数类取较大值/`nextReviewAt` 取较晚，自由文本（`aiExplanation`/`meaning`）按 `updatedAt` LWW；术语表 `note`、译本 `notes`：**LWW + 保存前版本检查**（提交时带 `lastKnownRev`，不匹配则提示用户选保留哪版） | 复习状态单调，可安全取大；自由文本并发编辑量小，LWW + 版本检查足够且有兜底提示 |
| 阅读偏好 / 设置 | SharedPreferences | LWW（整键） | 单值偏好，覆盖即可 |

**D-03（默认）**：冲突策略如上表；新增时间戳/rev 字段全部用 `opt*` 默认值，**不破坏老数据读取**。
**若你要「同一笔记并发编辑也自动合并」**：需要真正的文本合并（CRDT 或三方合并），属新范围，请明确——我不会默认引入。

## 5. 数据迁移、备份与回滚（验收标准 6）

现状：无 schema version、无备份、无回滚（阶段 0 §4.5）。设计：

1. **触发**：首次开启同步 / 首次运行新版本迁移时。
2. **备份（迁移前，强制）**：
   - 复制全部用户 JSON（`books/*/metadata.json`、`vocabulary.json`、`ai/**`、`voice_maps/**`、`translation-memory/**`）与偏好导出到 `filesDir/backup/<fromVersion>-<timestamp>/`；
   - 另生成可导出 zip（**排除书籍正文**）；
   - **备份失败 = 中止迁移**，不进入下一步。
3. **迁移**：新增 `filesDir/meta.json.schemaVersion`；对老数据补齐新字段（读写都走 `opt*` 默认值，故即使迁移中断也可读）；写入用「tmp + rename」原子替换（沿用现有落盘约定）。
4. **回滚**：记录 `backup/<...>/manifest.json`；提供「回滚到迁移前」入口，用备份覆盖并移除新增字段；回滚后再跑一次读取校验。
5. **验证**：迁移前后数据条数/内容守恒；备份→迁移→回滚往返一致（单元测试 + 真机/桌面各一次）。
6. **D-04（默认）**：备份保留策略 = 只保留最近 1 份迁移前备份 + 用户手动导出的包；不自动删用户手动包。
