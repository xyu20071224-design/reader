- 在集成 SHA 运行仓库要求的应用单测和 shared 测试，核对原始 XML 的失败、错误、跳过；有失败先定位并记录，不吞异常或改期望值凑绿。

- 当前版/跨版本说明、旧档案重新对齐、已保存生词/复习数据和原升级签名链不丢失。旧音频包按最终 pipeline 契约验：映射升版后不兼容包即使保留文件也不得用于新管线播放；只有映射不变且原始节奏回退已验证才可复用。版本/资产变化按项目发布规则处理。

## 台账与 GitHub 回填顺序

1. 子代理不直接改统一状态。集成人先依据报告更新 canonical_status.py 的现行依据，执行它生成 canonical_status.json，核对 34 个唯一 ID、总数和状态合计。
2. 在 VALIDATION.md 追加日期、集成 SHA 与实际验证结论；不改写 09 月旧快照、旧评论或原始反馈来抹掉历史。
3. 将 GitHub 两个 issue 各追加/更新一个简洁当前状态摘要，保留原文，链接对应提交与证据。只发送本次状态相关信息，不把整份无关历史记录贴到外部。
4. 当有可用写入权限时完成远端回填；权限仍不足则保留本地补丁和摘要，明确“尚未发布”，不得声称网页已更新。
5. issue 1 / issue 2 的关闭分别以其全部子项验收通过或有明确已确认的范围结论为条件。任一项仍待验/失败，保留打开并写出下一步。不得仅因本地未修复计数为零就关闭。
