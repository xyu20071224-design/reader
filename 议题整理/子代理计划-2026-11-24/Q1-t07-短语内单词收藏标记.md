# 短语内单词收藏标记验收

任务：Q1-t07。你负责完成本子项的复现、必要修复和验收。开始前读取 [总计划的共同执行约定](00-总计划.md#共同执行约定)，以其中指定的 GitHub 主分支基线建立隔离工作区。已有实现先验收；只有出现有证据的缺陷时才改产品代码。 来源：[issue 1 标题补充 7](https://github.com/xyu20071224-design/reader/issues/1)。

## 目标与当前依据

点击短语中的一个词时，收藏对象必须与用户当前看到的词/短语视图一致；已收藏对象在正文中有正确标记。单词与整条短语是两个可独立收藏的实体。不能让“想收藏单词却保存整条短语”被一条划线掩盖。

生产 `ReaderScreen` 通过 `lookupSession.vocabularyEntry(currentLookup)` 确定收藏词条；共享 `VocabularyRepository.save` 以 `matchedPhrase ?: headword` 为 ID，并累计 surfaceForms。该契约需通过实际面板切换验证。

## 执行步骤

1. 选择词典真实可识别的固定短语，如 look up / give up；先读取词典实际返回的 word/relatedPhrase，不假定所有词典包都识别相同短语。
2. 测试“显示单词后收藏”和“切换整条短语后收藏”两条路径，读取落盘 ID、headword、surfaceForms，并逐一核对正文标记、收藏按钮和复习卡。
3. 测试单词和短语分别存在、同时存在、仅删除其中一个；覆盖大小写、多空格、已见变形、跨行。跨 HTML 文本节点的短语若基线未支持，先明确重现与文本偏移契约，再决定最小节点映射方案。
4. 重启、换章、重新查询后再核对收藏身份，不能通过清空已有生词重测掩盖问题。
5. 若是视图/词条选择错误，定位到会话选择或保存入口；若是 DOM 匹配错误，交给标记模块所有者按 Q1-b01～t08 的串行安排修复。

## 改动边界

涉及 `ReaderScreen.kt` 的收藏接线、`ReaderLookupSheet.kt` 的视图入口、共享 `data/VocabularyRepository.kt` 与 `reader/ReaderCoreJs.kt`。与 Q2-c05 先统一“当前展示对象就是收藏对象”契约；不要同时修改 ReaderScreen。与 Q1-t09 的可见义项改动也必须串行集成。

## 验收条件

- 每次收藏的 ID、headword、正文标记和复习卡都对应用户实际选定的单词或短语。
- 删除单词不误删整条短语，反之亦然；重启后身份一致。
- 固定样本全部有应有标记，没有给无关单词或短语内部字母片段加线。
- 重叠标记采用共同规则，不能产生嵌套 span、改变正文或使点词偏移错位。

## 验证与交付

用生产词典配置和实际 WebView 执行设备验收，补充落库层和会话层必要回归。交付明确的“单词视图/短语视图→落库→标记→复习卡”逐步证据；无法确定收藏语义时先呈交冲突样本，不擅改产品定义。
