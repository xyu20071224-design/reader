# 词组收藏反馈一致性验收

任务：Q2-c05。你负责完成本子项的复现、必要修复和验收。开始前读取 [总计划的共同执行约定](00-总计划.md#共同执行约定)，以其中指定的 GitHub 主分支基线建立隔离工作区。已有实现先验收；只有出现有证据的缺陷时才改产品代码。 来源：[issue 2 评论 5](https://github.com/xyu20071224-design/reader/issues/2#issuecomment-5644352901)。

## 目标与当前依据

收藏词组时，用户看到的保存提示、收藏状态和复习条目都显示同一条完整词组。主分支中 AppViewModel.saveWord 的全局 notice 与 ReaderScreen 的内联反馈均已取 `entry.matchedPhrase ?: entry.headword`；旧“仍用 lookup.word”结论已经过时。

原反馈用过“通知栏”字样，后续定位曾反复改变。因此必须先记录真实出现问题的 UI，不预先把系统通知、听书条和收藏提示混为一谈。

## 执行步骤

1. 在实际词典可识别的短语中点击一个单词，切换单词/词组视图后分别收藏；先与 Q1-t07 固定收藏对象契约。
2. 面板保持打开时核对可见内联提示；面板关闭后另行核对全局反馈。验证落盘 ID/headword、复习卡和收藏按钮状态一致。
3. 覆盖移除、重复保存、保存失败、快速换到另一词条、保存完成前关闭面板、重启；旧请求的成功回调不能覆盖新词条的反馈。
4. 另看系统通知和听书条是否确实承载该操作。若出现原反馈现象，保存截图和入口复现后再定位；不为制造“已修”而给本无此职责的界面新增展示。
5. 现有代码通过时仅补验收和必要回归；真实失败时在对象选择或状态回调最小修复。

## 改动边界

`AppViewModel.saveWord`、`ReaderScreen` 的 onToggleSave、`ReaderLookupSheet` 状态展示、共享 VocabularyRepository；不改 TtsPlaybackEngine/通知服务来修收藏反馈。与 Q1-t07、Q1-t09 和 Q1-t11 的 ReaderScreen/ReaderLookupSheet 改动串行。

## 验收条件

词组视图的可见反馈与落库均为完整词组；单词视图仍为所选单词。失败时不得显示成功，快速切词不出现串词提示，重复收藏不误重置复习进度。不同 UI 的角色和测试结果有实际设备截图佐证。

## 验证与交付

复用 ReaderLookupVocabularyTest、ReaderVocabularyPersistenceTest 和实际保存回调测试，新增独立 PhraseSaveFeedbackInstrumentedTest 作为建议。报告附“当前面板对象→入库对象→可见反馈→复习条目”矩阵；若原现象无法复现，明确环境与已覆盖路径，不再保留未经验证的听书条根因。
