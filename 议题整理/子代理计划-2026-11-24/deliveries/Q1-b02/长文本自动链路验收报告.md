# Q1-b02 长文本自动翻译本地验收

代码基线为 Q1-t09 `f4901b5`，沿用 Q1-t01 已冻结的译本正文、检查点和句界侧车契约。本批先验收现有生产实现，只在出现真实断点后修产品代码。当前新增 `AiLongTextWorkflowAcceptanceTest`，未改对齐算法、批次算法或生产保存逻辑。

环境：macOS、JDK 17、Android SDK 35、Gradle 8.11.1；构建与 Android 用户目录、缓存、临时目录均重定向到隔离副本的 `artifacts/`。仓库要求的 `.agents/memory/MEMORY.md`、构建规则文件在本机副本及原目录均不存在，未引用其不存在的规则；遵循根 `AGENTS.md` 与主代理确认的 macOS 测试环境。

## 材料与链路

使用可从测试代码公开重建的合成 TXT：固定编号句 `Aster carried marker N through the silver valley.`，术语 Aster 明确设为保留原文。服务以确定性的本地桩提供 JSON，未发出真实 AI 请求。测试调用真实 `LibraryRepository.importDownloadedFile` → `AiTranslationRepository.translateBook`，没有通过手动导入译文替代自动编排。

- 无空行长章：350 行、无空行，经 TXT 导入后为一个超长原段。
- 混合书：普通段 + 400 句超长段 + 单个超过批上限的句子（2500 个短词）+ 400 句超长段 + 普通段，共五原段。
- 取消/续跑、单批失败、连续失败使用不同编号区间和源文件指纹，验证书 ID 与用户书籍无关。原始检查点不删除。

夹具输出只含 SHA-256、源文字符数、各原段长度、批次号/源文长度/原段索引、请求计数和失败段索引，不含授权头、Key 或私人书文。

## 验证范围

1. 每次请求的源文字符总数不超过既有 6000 上限，每个译块编号不重复；合并后原段数、次序、数字出现顺序和保留术语次数与源文对账。
2. 超长单句按词界硬切；测试桩局部替换可拼接，验证内容没有丢失或重复，不代表真实服务的跨块译法质量。正文按既定中文空串合并，比较时忽略排版空白，字符、标点与数字不忽略。
3. 首批完成后取消：已付出请求的检查点保留、没有发布译本；用新仓库实例续跑复用该检查点。此为新实例丢弃内存状态的恢复验证，不冒充设备进程被杀后的恢复。
4. 成功后仅使一个检查点指纹失效：只补发该批，其他已付检查点字节不变。
5. 一个长段中间译块两次失败：整原段回退英文，其他原段继续，最终原段不漏、不重、不换序。
6. 一批成功后连续三批各两次失败：第七次请求后中止，不发布译本，保留已成功首批检查点。
7. 无空行长章生成后，真实 `attachGenerated` 对齐、书库译本元数据保存、新书库/对齐仓库实例重开，首句与末句分别查到完整对应句译。这是仓库和持久化链路，未宣称书架界面或设备点击已验。

本次新增 5 例首次运行全部通过，未复现需要再改生产算法的断点。与原有 `AiTranslationRepositoryTest` 16 例及 Q1-t01 跨批句界 2 例合计 **23 tests / 0 failures / 0 errors / 0 skipped**。
