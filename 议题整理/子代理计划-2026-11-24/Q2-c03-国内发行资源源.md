# 国内发行与资源下载源完善

任务：Q2-c03。你负责实现受约束的国内分发源并完成真实可用性验收。开始前读取 [总计划的共同执行约定](00-总计划.md#共同执行约定)，按固定主分支基线建立隔离工作区。输出可复查证据，未完成的设备或服务验收必须保留。 来源：[issue 2 评论 3](https://github.com/xyu20071224-design/reader/issues/2#issuecomment-5565736791)。

## 目标与当前依据

GitHubUpdateChecker 固定 GitHub；AppUpdateRepository 的更新、包列表和下载沿用该源。NativePatchCatalog.trustedAsset 限制指定 GitHub 仓库 HTTPS，直接换域名会被拒。补丁现有大小、哈希、证书、精确基础 APK 和修订防重放校验必须保留。

交付源契约、客户端、静态目录/同步工具和实测。不得自行购买服务、部署公共站点、改域名或把用户数据 sync-server 改成公共文件托管。

## 执行步骤

1. 先提交规范化源接口：分开发布发现/历史目录、资产传输和发布身份/完整性，供 Q2-01 和现有更新/包列表共用。明确缓存归属和分页/不完整结果语义。
2. 定义可静态托管、版本化的目录，包含正式 release 历史、APK/包/补丁身份、大小、SHA-256 和基础包/修订约束；未知协议版本明确拒绝。
3. 实现 GitHub 与国内静态目录适配器，连接可注入、下载可取消；统一流式纪律并保留各资产上限与验证。哈希只证明匹配目录声明，目录/发布身份的信任来源必须另有明确约束。
4. 先评审镜像信任策略：区分 canonical 身份和传输 URL；约束可配置目录、资产与跳转，替代写死 host 时不删认证。APK 包名/签名/升级身份、补丁原证书/基础哈希/签名修订/防重放继续验证；包仍进 PackRepository、SafeZip、PackValidator。
5. 由集成人加源选择、当前源/失败反馈，自动检查默认仍关闭，备用源只按用户已选策略使用；缓存按源隔离，不静默连未知代理站。
6. 提供资产同步/目录生成工具：镜像原发布字节，校验后最后更新目录，不重建 APK 冒充原包。失败、取消、切源不复用另一资产的半截文件，不破坏已安装应用和资源。
7. 使用用户确认的真实国内服务做最终验收，明确 GitHub 不可达的网络条件；没有服务/权限/匹配签名产物时先交接口和工具，不伪报国内可用。

## 改动边界

本任务拥有发布源/适配器/下载抽象/源配置和目录工具，主导 GitHubUpdateChecker、AppUpdateRepository、AppUpdateSettings。NativePatchCatalog 的信任策略由集成人评审。Q2-01 拥有历史聚合/缓存，Q2-c02 拥有安装和消费；PacksSheet/UpdateSheet/AppViewModel/strings 由集成人接线。

## 关键用例与验收

两源各单独可用/均离线，同名异内容、错哈希/大小、HTML错页、截断/空文件、越界重定向、取消/重启/换源。错误 APK 身份、错误基础补丁、低/撤销修订、损坏或版本不兼容包均应拒绝。

fixture/本地服务证明两个适配器的发布身份和版本选择一致；真实国内源在 GitHub 不可达时可发现版本、下载并安装至少一个资源包，APK/补丁各按真实基线和签名条件完成验证。记录实际路径和回退原因。仅模拟请求通过不得关单。

## 验证与交付

交付协议稿、源/下载失败测试、生成与同步工具、脱敏网络结果、设备安装/回退证据和服务前提清单。可恢复原 GitHub 源；切换失败不丢资源。真实部署与付费操作由已有授权范围决定，缺条件交主代理处理。
