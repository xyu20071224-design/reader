## 共同执行约定

1. **先确定工作区和版本。** 开始时读取仓库 AGENTS.md、存在的 .agents/memory/MEMORY.md 和相关构建规则；缺文件如实注明，不能引用不存在的规则。更新远端引用并核对依赖提交。若 main 已前进，比较相关差异后修订基线，不强行退回本计划 SHA。
2. **保留用户工作。** 当前 /Users/clannad/work/reader/reader-1.2.0 有大量未提交更改，HEAD 落后已核对的远端；只作参考，不允许 reset/clean/覆盖或直接混入修复。主代理用工作区工具分配隔离工作区和 feat/issue-<id> 分支；本轮制定计划不创建执行分支。每个工作区只改自己负责的文件。
3. **明确生产链。** 对齐只沿 shared.translation 与 app.translation 验证，shared.alignment 尚未接生产。阅读 JS 已拆为 ReaderScripts、ReaderCoreJs、ReaderCss 等，不能只依据旧 ReaderScripts 大文件行号定位。
4. **先证据后修改。** 留最小复现、固定输入和预期，再针对实际断点做最小改动。不得降低断言、删除金标准、放松阈值或用 skipped/吞异常让测试变绿。确需改变既定语义时先提交变更理由和影响样本给集成人裁定。
5. **设备与构建各归其位。** 纯逻辑改动运行项目要求的应用单测及关联 shared 测试；WebView/手势/TTS/通知改动必须真机或合适模拟器。听感和原用户设备问题需要真实输出证据。XML 的 tests/failures/errors/skipped 和原始输出是依据，不只看退出码。
6. **先识别当前平台工具链。** Linux 用 toolchain/build.sh，旧 Windows 按仓库验证约定；当前是 macOS，不直接执行 Linux JDK/SDK 二进制，也不以“命令跑不了”当测试通过。由集成人确认可用的本地或 CI 环境和设备。Gradle 根是 src/，:shared 用 :shared:test。
7. **隔离验证产物。** 不同任务使用不同工件目录和测试结果目录；同一设备、同一 verify 包同一时段只交一个代理。connectedDebugAndroidTest 收尾可能卸载 verify 包，所需现场证据在收尾前取得，不能影响其他验收。
8. **共享接线集中合入。** MainActivity、AppViewModel、ReaderScreen、ReaderLookupSheet、UpdateSheet、PacksSheet、公共模型、pipeline/cache/包格式和两套 strings 由指定所有者串行编辑；其他代理交最小接线需求或补丁。每个任务新建独立测试类，避免同时改通用仪器测试文件。
9. **保留产品约定。** 共享层不依赖 android.*；双语资源同步；联网能力默认零新增请求，失败有离线行为；成功/失败反馈可见。仅使用已授权服务，Key 由用户现有配置持有，不进入代码、报告或日志。
10. **真实交付。** 每个代理交报告、最小补丁/提交和证据清单；不自行修改统一 canonical_status、发布汇总评论、关闭汇总 issue、创建 Release、部署或更改版本签名。集成人按证据统一处理。大音频/截图/模型/书籍放忽略的 artifacts 下，不进 Git。
11. **不能完成时明确边界。** 无真实素材、引擎、设备、服务或域名时，先完成不依赖它的工作，报告具体待验条件；不能用模拟结果冒充真实成功，也不把范围不明的功能顺手扩成新项目。

## 子代理交付格式

每项报告保存为 deliveries/<子项 ID>/报告.md，并包含：

- 任务 ID、实际分支/提交、代码基线和环境；
- 原缺陷是否复现、最小输入、根因或“未复现”的已覆盖范围；
- 修改文件与行为、与共享接口的关系；
- 每条验收条件的通过/失败/待验及对应 XML、截图、录音或网络结果；
- 仍有风险、回退方式、请求集成人处理的共享修改；
- 建议状态，只能由集成人在总表中回填。

收到单份“代码完成”后，不直接把整条 issue 1 或 issue 2 关闭。最终关闭条件见[总验收与状态回填](90-总验收与状态回填.md)。
