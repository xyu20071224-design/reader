# 发布版本改动汇总与常驻入口

任务：Q2-01。你负责让测试者随时阅读本版说明并查看跨版本升级改动。开始前读取 [总计划的共同执行约定](00-总计划.md#共同执行约定)，按固定主分支基线建立隔离工作区。输出可复查证据，未完成的设备或服务验收必须保留。 来源：[issue 2 正文](https://github.com/xyu20071224-design/reader/issues/2)。

## 目标与当前依据

GitHubUpdateChecker 只取 releases/latest，GitHubReleaseParser.parse 无 APK 时可返回 null，UpdateSheet 仅 AVAILABLE 路径展示一次 releaseNotes。不能只拉多页 releases 就宣称“上次发布到本版改动”已完成，须覆盖发布资料与本版离线说明。

## 执行步骤

1. 固定两种范围：“本版改动”绑定上一个正式 release 到当前 release 的提交边界；“本次升级”汇总上次实际安装版本到当前版本。首次安装无旧版本时不虚构起点；热补丁修订号独立于 APK 版本。
2. 新建独立发布说明模型和纯聚合器，携带 release/tag/版本/时间/正文/来源/提交与完整性；按版本区间排序去重。说明解析与是否含 APK 分离。
3. 使用 Q2-c03 先交付的规范化 ReleaseSource 分页接口，先接 GitHub；历史缓存由本任务所有，不自造第二套网络协议。
4. 增加发布时生成说明的工具：从明确正式发布边界整理 commit/PR 改动，绑定 tag/commit；应用运行时不抓取全部提交。准备与实际构建版本一致的内置本版资料。
5. 增加历史缓存与安装版本记录：启动只读本地，明确刷新才联网；缓存损坏回退内置本版说明/可见空态，读失败不推进已阅状态，分页失败标未完整。
6. 经集成人接入书架常驻“版本改动”，最新版、断网、检查更新失败时仍能看本地说明；历史状态独立于下载/取消/补丁应用。
7. 验跨版安装、首次安装、同版本重启、降级、热修复和缺说明，不能以空内容冒充范围内无改动。

## 改动边界

独占新 ReleaseHistory 模型/聚合/缓存/生成工具及测试。GitHubUpdateChecker 的统一传输/分页由 Q2-c03 所有；AppViewModel、AppUpdateUiState、UpdateSheet、书架入口和 strings 交集成人串行接线。不改补丁应用、APK安装、资源包安装。内置 assets 变化按项目规则走新 APK，不当作 DEX 热补丁交付。

## 关键用例与验收

至少两页、页间重复、发布时间乱序、1.9→1.10、无 APK release、空说明、未知 tag、draft/prerelease 渠道过滤。选定旧/中间/当前版本 fixture，显示集合与预先定义集合完全相等。第一页成功第二页失败不得显示“无改动”。

真实书架常驻入口在当前最新版与离线可读；本版说明追溯到两端 tag/commit，跨版记录真实；查看说明不下载，取消下载不清历史，自动检查关闭时启动/本地查看零新增请求。

## 验证与交付

纯聚合/解析/缓存用例、应用状态/UI 回归、设备离线与跨版证据，另交发布资料生成与构建产物版本一致性验证。缺真实资料/设备时保持发布/真机待验。
