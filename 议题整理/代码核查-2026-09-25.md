## 3. `Q2-c04c`：从「不可复现」到**定位 + 修复**（本轮唯一代码改动）

### 3.1 原台账为什么判「不可复现」

台账结论「当前代码 7/14 个变体均不复现」只在**分句器一层**成立：`议题整理/SplitProbe.java` 只反射调用了 `SentenceSplitter.split`，而缺陷在更下层，探针的 U+2019 变体**从未到达** `QuoteSpans`/`TtsChapter`。属**分层漏测的假阴性**。

### 3.2 真实机制（对抗复核员定位，本次实测确认）

- `QuoteSpans.kt` 的 `normalizeQuotes` 把弯引号折成 ASCII `"`，注释写着「**ASCII** 撇号有意保留」——但实现把 `’`(U+2019) 也一并折了。真实英文书正文用的正是 U+2019，于是 `her’s` / `don’t` 凭空开出一个**未闭合引语区间**。
- `TtsChapter.segmentRuns` 在该区间裂句 → 撇号处断成两段，后半段被 `SpeakerRuleTagger` 判成 **dialogue**；带 speaker 标签的章节 `mergeSameSpeaker` 合不回去（无标签章节两段同声部会被合并，所以只有主流程听得出来）。
- 未闭合引语还会 **carry 进下一块**，污染下一段的引号配对。

### 3.3 红阶段原始证据（子代理留证，XML）

```
wordInternalCurlyApostropheIsNotAQuote
  expected:<[]> but was:<[10..21]>                    # her’s 的 U+2019 开出到块尾的未闭合区间
wordInternalCurlyApostropheDoesNotSplitSentenceIntoSegments
  expected:<[It was her’s., He left.]> but was:<[It was her, ’s., He left.]>
curlyApostropheInsideDoubleQuotedSpeechKeepsThePair
  expected:<[0..14]> but was:<[0..6, 14..23]>          # 引号配对被撇号打断
```
新增 `QuoteSpansTest`（8 例），红阶段 **8 tests / 6 failed**。

### 3.4 修复

`QuoteSpans.kt`：`’` 仅当**词内**（两侧都是词字符）时保留撇号语义，其余照旧折成 `"`；`‘`/`“`/`”` 行为不变。

```kotlin
val quote = char == '‘' || char == '“' || char == '”' ||
    (char == '’' && !isWordInternalApostrophe(block, index))
```

最小性：只动折引号这一处（`spans`/`segmentRuns`/`SentenceSplitter` 全未改）、仍是**逐字符等长替换**（坐标不变量保持）、词尾 `’` 保留引号语义因而 `‘Hello there.’`/`“Fly!”` 等成对引号行为不变。

**并按 `QuoteSpans` 头部契约补上必须的一刀**：`TtsPipelineContract.VERSION` **2 → 3**（改片段规则不 bump 会让存量 `s<句>-<段>` 缓存指向另一段文本，且不会有任何报错），同步改 `scripts/build_audio_pack.py` 的 `PIPELINE_VERSION`、`TtsCacheKeyTest` 的钉值、`TtsAudioCache` 的注释与 `方案-资源包系统.md` 实施记录。代价是存量音频缓存与 v2 音频包按契约失效（重听会重新合成）。
